## 1.2.8 — OPEN: подтверждённые ограничения штатных дополнений (22.11.2026)

**Матрица поддержки:** miniShop2 — **только MODX 2**; на MODX 3 miniShop2 не устанавливаем и не проверяем. MiniShop3 — другое дополнение/API, отдельная будущая интеграция, не автоматическая замена существующим `ms2_*`. Для miniShop2 положительное CAS-E2E на MODX 2 достаточно для включения сценария в реестр. Неподдерживаемая платформа не считается пропущенным обязательным тестом.

**Статус: остаются индивидуальные E2E-ограничения и release-gates.** miniShop2 проверяется только на MODX 2; общий MODX MCP сохраняет тесты MODX 2/3 для поддерживаемых инструментов. P0 fail-closed остаётся приоритетным.

- [x] **Закрыто как неверная цель тестирования:** miniShop2 4.4.2-pl требует MODX 2 и не поддерживает MODX 3; обнаруженный в PR #136 fatal отсутствующего `core/model/modx/modprocessor.class.php` — доказательство неправильной тестовой матрицы, не задача адаптировать miniShop2 под MODX 3. Для MODX 3 отдельно оценивать MiniShop3 и её API. Не добавлять совместимые shim в общий MCP.
- [x] **miniShop2 / создание категории и назначение опции на MODX 2:** в независимом E2E на одноразовом MODX 2.8.9/PHP 8.2 подтвердились `ms2_create_category` и `ms2_assign_option_to_category`: штатные процессоры, чтение через MCP, отказ stale replay; в обвязку MCP добавлено обязательное пустое значение `msCategoryOption.value` (`NOT NULL` в native схеме). Прогон PR #152 — 12/12 и 4/4; итоговые сценарии будут закреплены в отдельном rebased PR. **`ms2_update_category` остаётся не подтверждённой.**
- [x] **miniShop2 / обновление категории на MODX 2:** независимый E2E с собственной неопубликованной `msCategory`, штатным `resource/update` через MCP, обязательным полным контекстом (`context_key`, `class_key`, `parent`, `alias`), CAS+1, MCP readback и отказом stale replay прошёл в PR #154 (12/12; CI 4/4). Этот узкий сценарий учтён в реестре с `disposable_modx2_*`. **Версия VersionX 3.x использует иной API `deltas/revert`** (`type`, `principal`, `delta_id`, `what`) и требует самостоятельной интеграции, независимой авторизации, реального E2E на установленной MODX 3; старый processor не подменять. P0 fail-closed после попытки восстановления уже принят через PR #149. Поддержка 3.x остаётся открытой, но не отменяет доказательство 2.4.0.

- [ ] **miniShop2 / `ms2_update_order` — смена статуса и частичный эффект:** Положительное обновление комментария реального собственного заказа на disposable MODX 2.8.9/PHP8.2 с MCP readback/CAS/stale replay успешно прошло (PR #156, прогон #45065354009). Fail-closed `MUTATION_OUTCOME_UNCERTAIN` уже добавлен в PR #144, но дополнительно требуется реальный E2E перехода статуса и fault-after-save через MCP, независимый `ms2_get_order`, без автоматического повтора или ложного `not_applied`. ## Первоначальное получение API-токена после установки

- **Статус:** закрыто в 1.2.2 (2026-10-12).
- **Обнаружено:** 2026-10-10, при чистой установке MODX MCP 1.2.1.
- **Проблема:** компонент автоматически создаёт API-токен при установке, но в интерфейсе управления показывает только маску (начало и конец токена). Пользователь не может скопировать полный первоначальный токен для подключения MCP-клиента и вынужден выпускать новый.
- **Решение:** кнопки «Показать» и «Скопировать» получают существующий токен по отдельному запросу менеджера с правом `settings`; полный токен не включён в исходный HTML. Новый токен генерируется только по явному действию с предупреждением о разрыве старых подключений. Платформенные процессоры предусмотрены для MODX 2 и MODX 3. Проверены сборки и работа MCP после установки; полный автоматический тест нажатий в менеджере не заявляется.

## Документация системных настроек MODX MCP

- **Статус:** закрыто (2026-10-12); справочники для версии 1.2.2.
- **Обнаружено:** 2026-10-10, при первоначальной настройке MODX MCP 1.2.1.
- **Проблема:** системные настройки компонента в менеджере MODX недостаточно понятны без подробных объяснений; пользователю трудно определить, что именно регулирует параметр и когда его менять.

Полнота сверена с общим для MODX 2/3 файлом `_build/data/transport.settings.php`, ссылки добавлены в README и обе инструкции установки. Код административного интерфейса не менялся.
