# MODX MCP — технический справочник инструментов

**Русская редакция · API 1.2.0 · 10 октября 2026 года**

[English](API.md) | **Русский** · [Установка](INSTALL.ru.md) · [Возможности](CAPABILITIES.ru.md) · [Безопасность](SECURITY.ru.md)

Этот справочник предназначен для разработчиков, авторов MCP-клиентов и пользователей ИИ-агентов, которые работают с **MODX Revolution 2.8.x и 3.x** через [MODX MCP](https://github.com/rumata-estor/modx3-mcp). Он объясняет публичный интерфейс компонента: какие инструменты доступны, что они делают, какие аргументы принимают и какие ограничения нужно учитывать. Внутренняя инфраструктура пользователей компонента здесь не рассматривается.

> **Версия интерфейса.** В `client/index.js` версии 1.2.0 объявлен **191 публичный MCP-инструмент** `modx_*`. Серверный реестр содержит **192 действия**: дополнительное `get_capabilities` используется клиентом для согласования доступных возможностей и не выставляется как отдельный публичный MCP-инструмент. Набор инструментов, который увидит конкретный пользователь, может быть меньше: зависит от версии сервера, настроек и установленных дополнений.

## Подключение MCP-клиента

После установки транспортного пакета **для своей версии MODX** используйте стандартный MCP-клиент с поддержкой `stdio`. Клиентская часть требует **Node.js 18+**. Пример общей конфигурации (конкретное место настройки зависит от используемого MCP-клиента):

```json
{
  "mcpServers": {
    "modx": {
      "command": "npx",
      "args": ["-y", "github:rumata-estor/modx3-mcp#v1.2.0"],
      "env": {
        "MODX_MCP_SITE_URL": "https://example.com/assets/components/modxmcp/api.php",
        "MODX_MCP_TOKEN": "ВАШ_ТОКЕН_MODX_MCP"
      }
    }
  }
}
```

`MODX_MCP_SITE_URL` — HTTPS-адрес API установленного компонента, а `MODX_MCP_TOKEN` — значение настройки `modxmcp.api_token` **именно этого сайта**. На боевом сайте закрепляйте стабильный тег, а не `main`. Установка пакета и подробная совместимость описаны в [README.ru.md](../README.ru.md).

**Важно:** Node.js-часть — **локальный MCP-сервер**, общающийся с агентом через `stdio`. Сайтовый PHP endpoint — **HTTP API**. Это разные интерфейсы одной системы; не направляйте MCP-протокольные сообщения `tools/call` непосредственно в `api.php`.

## Как устроен вызов

При вызове инструмента MCP его имя имеет префикс `modx_`, например `modx_get_element`. Стандартный клиент преобразует его в серверное действие `get_element`.

**MCP-вызов** (содержимое параметров `tools/call`):

```json
{
  "name": "modx_get_element",
  "arguments": {"type": "snippet", "name": "SiteMenu"}
}
```

**Соответствующий запрос в HTTP API** (только если вы самостоятельно разрабатываете интеграцию):

```http
POST /assets/components/modxmcp/api.php HTTP/1.1
Host: example.com
Content-Type: application/json
X-MCP-Token: <секретный токен>

{"action":"get_element","type":"snippet","data":{"name":"SiteMenu"}}
```

Общий формат HTTP-запроса: `action` — имя серверного действия **без** `modx_`; `type` — тип элемента, если нужен; `data` — объект аргументов. Для некоторых элементных операций тип передаётся отдельно на верхнем уровне, как в примере. Для прочих операций достаточно `action` и `data`. Параметры конкретных инструментов далее описаны **в формате MCP**, которым разработчик обычно пользуется.

Успешный HTTP-ответ имеет форму:

```json
{"success":true,"data":{"...":"..."},"caps":"..."}
```

Поле `data` содержит полезный результат — объект, список, строку или другой тип в зависимости от операции; `caps` используется для согласования списка возможностей. При ошибке передаётся `success: false` и поле `error`.

## Условные обозначения

В каждой карточке указываются название инструмента, его назначение, тип операции, все обычные публичные параметры и обязательность согласно `inputSchema` MCP-клиента.

- **Чтение** — запрос не предназначен для изменения содержимого сайта.
- **Изменение** — операция может создавать или изменять данные.
- **Повышенный риск** — удаление, массовая операция, изменение доступа, учётных записей, ключевых настроек или другой потенциально необратимый результат.

Типы: **строка** (`string`), **число** (`number`), **целое число** (`integer`), **логическое** (`boolean`), **массив** (`array`), **объект** (`object`). Для логических полей передавайте JSON `true`/`false`, не текстовые строки. Числовые переключатели MODX (`active`, `published` и т. п.) в некоторых схемах объявлены как `number` и обычно принимают `0`/`1`.

**«Обязателен по схеме» не всегда означает «достаточен для выполнения».** Некоторые команды принимают альтернативные способы идентификации (`id` или `name`): оба поля формально необязательны, но практически требуется одно из них. Такие условия указаны в примечаниях. Схема описывает запросы, но сервер выполняет дополнительную предметную проверку и проверку прав.

Описание полей основано на текущей схеме клиента. Фактическая поддержка дополнений и операций зависит от версии серверной части, конфигурации, прав сервисного пользователя и установленных компонентов. Внутренние служебные поля интеграций не входят в публичный справочник.

**Тип операции:** Повышенный риск.

| Параметр | Тип / значения | Обязателен | Назначение |
| --- | --- | :---: | --- |
| `operation` | строка; варианты: `publish`, `unpublish`, `set_template`, `move`, `delete` | да | операция, применяемая к выборке ресурсов |
| `ids` | массив чисел | нет | массив идентификаторов ресурсов |
| `parent` | число | нет | идентификатор родителя или каталог для вложения |
| `context` | строка | нет | ключ контекста MODX |
| `query` | строка | нет | строка поиска или фильтрации |
| `template` | целое число | нет | идентификатор шаблона или шаблона политики — в зависимости от команды |
| `parent_to` | число | нет | новый родительский ресурс |
| `context_to` | строка | нет | новый контекст |
| `dry_run` | логическое | нет | предпросмотр без записи данных |
| `limit` | число | нет | максимальное количество записей |

**Примечание:** Операция `delete` отправляет ресурсы в корзину MODX (мягкое удаление). Для `set_template` заполните `template`; для `move` — `parent_to` и/или `context_to`. Цели выбираются через `ids` или фильтры. Перед записью сначала `dry_run: true`.

## Краткие примеры запросов

Это **примеры отдельных вызовов публичного MCP API**, а не готовые автоматизированные сценарии работы агента. Значения ID и имён в примерах условные.

### Получить список сниппетов

```json
{"name":"modx_list_elements","arguments":{"type":"snippet","query":"menu","limit":20}}
```

### Прочитать чанк по имени

```json
{"name":"modx_get_element","arguments":{"type":"chunk","name":"site_header"}}
```

### Найти строку в коде сайта

```json
{"name":"modx_search_code","arguments":{"query":"pdoResources","types":["snippet","chunk","template"],"limit":30}}
```

### Посмотреть связи указанного чанка

```json
{"name":"modx_dependency_graph","arguments":{"focus":"chunk:site_header","depth":2,"direction":"both"}}
```

### Просмотреть часть сниппета с номерами строк

```json
{"name":"modx_view_element","arguments":{"type":"snippet","name":"SiteMenu","start_line":1,"end_line":80}}
```

### Проверить массовое изменение без записи

```json
{"name":"modx_bulk_resources","arguments":{"operation":"set_template","ids":[17,18,19],"template":4,"dry_run":true}}
```

### Проверить замену строки в чанках без записи

```json
{"name":"modx_replace_across","arguments":{"find":"old-class","replacement":"new-class","types":["chunk"],"case_sensitive":true,"dry_run":true}}
```

### Прочитать TV ресурса

```json
{"name":"modx_get_resource_tvs","arguments":{"resource_id":17}}
```

### Создать простой чанк (только при разрешённой операции)

```json
{"name":"modx_create_element","arguments":{"type":"chunk","name":"notice_banner","content":"<div class=\"notice\">Текст</div>"}}
```

Создание и изменение могут требовать дополнительных разрешений, защиты клиента или установленного компонента. Не переносите примеры записывающих вызовов на рабочий сайт без проверки результата и резервной копии.

## Ошибки и проверка доступности

| HTTP-код | Смысл | Что проверить |
| --- | --- | --- |
| `200` | Запрос обработан | Читайте `success` и `data` в теле. |
| `400` | Некорректное действие/аргументы или ожидаемая прикладная ошибка | Поле `error`, имя команды, тип, идентификаторы и требуемые поля. |
| `401` | Неверный или отсутствующий токен | `MODX_MCP_TOKEN` и настройку `modxmcp.api_token`. |
| `403` | Запрос не разрешён | Включён ли MCP, HTTPS, ограничения по IP. |
| `405` | HTTP-метод не поддерживается | Для команд используйте `POST`. |
| `413` | Слишком большой запрос | Размер тела и настройку `modxmcp.max_payload_bytes`. |
| `500` | Неожиданная ошибка сервера | `error_id` и журнал ошибок MODX; не включайте подробный вывод в публичных окружениях. |

**Быстрая проверка доступности:** `GET` к endpoint возвращает общие сведения (`component`, `version`, `variant`, `enabled`) без аутентификации, но под защитой HTTPS. Такой запрос не проверяет исправность или права отдельных команд. Для проверки набора действий вызывайте через MCP `modx_list_actions` и `modx_check_integrations`, а через `modx_help` читайте встроенную справку.

Не следует считать все 191 инструмента гарантированно доступными на любом сайте. Стандартный клиент сравнивает объявления с действиями сервера и отключёнными группами. Дополнительные инструменты, относящиеся к MIGX, miniShop2, VersionX, VirtualPage и ClientConfig, зависят от установленных дополнений.

## Ограничения и безопасность

1. **API-токен даёт высокие полномочия.** После проверки токена сервер выполняет операции от имени служебного пользователя MODX с правами `sudo`. Защищайте токен как административный секрет. Не включайте его в репозитории, тексты задач, общедоступные журналы и примеры конфигурации.
2. **HTTPS должен оставаться включённым.** Дополнительно можно ограничить IP-адреса через `modxmcp.allowed_ips`. Настройки по умолчанию не заменяют сетевую защиту и защиту от перегрузки.
3. **Клиент и сервер — разные уровни защиты.** Часть проверок и автоматических резервных копий выполняется стандартным Node.js-клиентом. Прямые HTTP-запросы к endpoint **не проходят через эти клиентские проверки**. Разработчик собственного клиента обязан реализовать необходимые подтверждения, контроль резервных копий и ограничения операций самостоятельно.
4. **Отключённые группы — не полноценная ролевая модель для обладателя токена.** Настройка `modxmcp.disabled_groups` уменьшает набор доступных функций, но не заменяет изоляцию токена и контроль доступа на границе API.
5. **Массовые операции проверяйте заранее.** Для `modx_delete_element`, `modx_bulk_resources`, `modx_replace_across` используйте `dry_run`. Для `modx_clear_tv_values` и `modx_versionx_revert_version` требуется отдельное подтверждение.
6. **Будьте осторожны с настройками и секретами.** Команды чтения системных настроек могут возвращать секретные значения; не отправляйте полные ответы в публичные чаты или отчёты. Менять токен, права, процессоры и настройки авторизации следует только осознанно.
7. **Не предполагайте поддержку произвольного PHP/SQL/SSH.** MODX MCP предоставляет ограниченный набор операций над MODX. `modx_run_processor` по умолчанию отключён и требует специальной настройки `modxmcp.allow_run_processor`.
8. **Не считайте `Чтение` признаком общедоступности данных.** Даже операции чтения могут возвращать персональные данные, исходный код и закрытые настройки. Они требуют авторизации.

### Что относится к MODX 2 и MODX 3

Обе платформы используют один публичный набор инструментов MCP, но установочные транспортные пакеты различаются: `modx2mcp` для MODX 2.8.x и `modx3mcp` для MODX 3.x. Фактические возможности зависят от работающих процессоров MODX и установленных сторонних дополнений. Перед автоматизацией операции проверяйте наличие действия на **конкретном сайте**.
