# MODX MCP 1.2.8 Beta 1 — программа тестирования

**Статус: кандидат, не стабильный релиз.** Транспортные пакеты MODX 2/3 и Node MCP-клиент собираются и проверяются в GitHub Actions. Пакеты пока **не публикуются** как стабильное обновление и не загружаются в официальный каталог Extras MODX.

> **Принцип безопасности.** Мы не гарантируем математическое отсутствие всех конфликтов; мы гарантируем предсказуемое поведение системы и честное сообщение об ограничениях.

Изменения и полное описание принятых ограничений: [Ограничения безопасности 1.2.8 Beta](SECURITY-LIMITATIONS-1.2.8.ru.md).

## Что тестируем

Это крупное обновление механики безопасности, а не обычный выпуск функций:

- Обязательные CAS-предусловия для изменяющих команд; клиент должен прочитать актуальное состояние перед записью.
- Отказ `STALE_STATE` при конфликте с другим MCP-клиентом или при обнаруженном изменении через MODX Manager.
- Повторная проверка исходных TV перед `setTVValue()` штатным MODX API. Остаётся ограничение по гонке с внешней записью после проверки.
- Для перезаписи медиафайлов — обязательный `expected_sha256`, полученный при полном проверяемом чтении. Для неизвестного драйвера или неполного снимка автоматическая перезапись не поддерживается.
- Изменение/удаление политик доступа и их шаблонов требует полного снимка целевого объекта из `get_site_state.read_set`. Конкурирующие правки остальных сущностей ACL не объявляются атомарно защищёнными.
- Отказы `MANUAL_REVIEW_REQUIRED` и `MUTATION_OUTCOME_UNCERTAIN` требуют остановки и проверки человеком; автоматический повтор или компенсирующий откат при неизвестном результате недопустим.
- Исправления файлового режима `portable`: для **перезаписи существующих статических файлов** проверяются ACL/xattrs через внешний инспектор; если проверка недоступна, операция отклоняется. Для опасных локальных конкурентов используйте `strict`; режим `portable` не гарантирует отсутствие TOCTOU.
- Сохранность существующего токена и пользовательских настроек при обновлении с 1.2.7.

## Безопасный порядок испытаний

1. **Только тестовый сайт.** Сделайте отдельные резервные копии файлов и БД, запишите используемые расширения и версию PHP. Не обновляйте production или общие клиентские сайты.
2. Установите пакет для своей платформы через **MODX Manager → Управление пакетами**; при переходе с `1.2.7` выполните обычное обновление, не переименовывая пакет. Убедитесь, что прежний токен и индивидуальные настройки сохранены. Для новых установок компонент по умолчанию выключен до ручного включения.
3. Обновите Node MCP-клиент. Выполните только чтение: `modx_get_site_state`, сведения о сайте и чтение заведомо тестовой неопубликованной страницы.
4. Для изменения собственного тестового объекта сформируйте свежий `read_set`/CAS-снимок, выполните одну запись, прочитайте результат через MCP, затем подтвердите отказ при повторе со старым снимком.
5. На отдельном неопубликованном ресурсе измените TV из Manager между чтением и попыткой MCP-записи. Ожидается `STALE_STATE` (если изменение замечено до выполнения). Не пытайтесь искусственно вызывать гонки на рабочем сайте.
6. На тестовом медиафайле проверьте, что обновление без `expected_sha256` отклоняется, а со свежим подтверждённым хешем выполняется; изменённый после чтения файл должен давать `STALE_STATE`.
7. Для ACL используйте только собственную **невыданную** тестовую политику/шаблон. Проверяйте отказ без целевого fingerprint; не выдавайте дополнительные полномочия реальным пользователям ради теста.
8. При неожиданном сообщении прекратите запись. Не делайте автоматический повтор или «откат наугад». Сравните текущее состояние через MODX и сообщите наблюдения разработчикам.

При недостающем индексе ACL проверьте инструкцию [миграции ACL](../_build/migrate-acl-index.php) и параметры самой утилиты; её применение изменяет схему БД и требует отдельного решения администратора. **Beta не запускает эту миграцию автоматически.**

## Дополнительная проверка безопасности файлов (FINDING-006)

На тестовом сайте прочитайте обычный файл компонента с помощью `modx_read_component_file`. Затем попробуйте прочитать ссылку на файл вне каталога компонента. Ожидается отказ; содержимое внешнего файла в ответе недопустимо. На POSIX-хосте для защищённого чтения обязательны Python 3 и `proc_open`; отсутствие зависимостей должно приводить к `MANUAL_REVIEW_REQUIRED`, а не к незащищённому чтению. Для каталогов, организованных через симлинки, возможен намеренный отказ даже при безопасной цели.

## Как сообщить о проблеме

Создайте [GitHub Issue](https://github.com/rumata-estor/modx3-mcp/issues) с версией MODX/PHP, вариантом пакета, `SOURCE_COMMIT.txt`, типом Media Source (если применимо), именем операции и кодом ошибки, ожидаемым и фактическим результатом, а также указанием, изменилось ли состояние объекта. **Не прикладывайте токены, закрытые ключи, пароли, персональные данные, реальные медиа или необработанные логи с секретами.**

## Откат

Если результат неизвестен, сначала остановите клиента и установите фактическое состояние. Не пытайтесь «повторить пока не пройдёт». Возврат к 1.2.7 **не должен выполняться простым переименованием или установкой старого ZIP поверх Beta**: сначала восстановите проверенную резервную копию файлов и БД тестового сайта. Запишите инцидент и только затем продолжайте.

**Критерий перехода к публичному Beta:** обе установки и обновления 1.2.7→Beta, обязательный CAS, демонстрационные конфликты TV/media/ACL, корректные сообщения об отказе и сохранение настроек подтверждены. Остаточные ограничения описаны в отдельном документе.
