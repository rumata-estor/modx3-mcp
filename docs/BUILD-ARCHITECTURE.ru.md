# Архитектура сборки

## Подготовка исходников релиза 1.2.5

Управление категориями реализовано в общем модульном ядре и входит в оба платформенных дерева сборки. Для будущих пакетов MODX2MCP и MODX3MCP предусмотрен единый контракт из 199 серверных действий (198 публичных инструментов MCP). До публикации необходимо собрать ZIP и проверить установку на тестовых сайтах.

> Документация пользователя: [установка](INSTALL.ru.md), [возможности](CAPABILITIES.ru.md), [API](API.ru.md), [безопасность](SECURITY.ru.md).

Из одного дерева исходников коннектора собираются два варианта релиза:

- **MODX Revolution 2.8.x** — идентификатор платформы `modx2`, транспортный пакет `modx2mcp-<version>-pl.transport.zip`;
- **MODX Revolution 3.x** — идентификатор платформы `modx3`, транспортный пакет `modx3mcp-<version>-pl.transport.zip`.

Обе сборки используют один MCP-клиент, один публичный контракт действий и одну модульную среду выполнения из `core/components/modxmcp/src/`.

Общая кодовая база включает:

- `core/components/modxmcp/src/`;
- классы инструментов, реестр, дополнительные модули, логику точки входа API и документацию;
- общие ресурсы интерфейса и логику менеджера там, где MODX 2 и MODX 3 работают одинаково.

Платформенные файлы сборки и загрузки находятся в `_build/platform/<platform>/`. Скрипт `_build/prepare-release.py` создаёт чистое подготовительное дерево для выбранной платформы и накладывает только нужный платформенный слой.

Архитектура специально избегает проверок версии, разбросанных по прикладным классам инструментов, например `if (MODX_VERSION...)`. Различия MODX 2 и MODX 3 изолированы на границе загрузки и сборки и за интерфейсом `PlatformInterface`.

## Подготовка дерева релизной сборки

MODX 3:

```bash
python3 _build/prepare-release.py --platform modx3 --output /tmp/modxmcp-modx3
```

MODX 2:

```bash
python3 _build/prepare-release.py --platform modx2 --output /tmp/modxmcp-modx2
```

Каждый транспортный пакет нужно собирать на установке MODX той же основной версии.

**Исправление для следующей сборки (после v1.2.2):** общий `_build/transport.documentation.php` превращает относительные ссылки README и CHANGELOG в абсолютные адреса GitHub **только внутри метаданных пакета**. Исходная документация не меняется. Добавлен PHP-тест; содержимое метаданных проверено в двух пробных ZIP для MODX 2/3. В опубликованные архивы v1.2.2 это изменение **не входит** и появится только в следующем релизе.

## Сборка версии 1.2.3 для двух платформ (12.10.2026)

Сборщики MODX 2 и 3 преобразуют относительные ссылки README и CHANGELOG **только в метаданных транспортного пакета**, закрепляя ссылки и изображения за тегом версии вместо адреса менеджера MODX. Исходные файлы Markdown не меняются. Оба ZIP прошли проверку целостности и ссылок в манифестах, установлены на тестовые сайты, сохранили все 16 настроек и токен и прошли авторизованные проверки API только для чтения (193 серверных действия).

## Текущий релиз: сборка версии 1.2.2 для двух платформ

Пакеты сохраняют разные идентификаторы `MODX2MCP` / `MODX3MCP` и общее пространство `modxmcp`. При подготовке сборки MODX 2 подставляются совместимые контроллеры `index` и `graph` и процессоры `gettoken3` / `savesettings3` на базе `modProcessor`. Адаптивные шаблоны, CSS/JS графа и словари общие. **Опубликованный** контракт v1.2.2 содержит 193 серверных действия (81 чтение / 112 изменений): 192 публичных инструмента MCP и внутреннее действие `get_capabilities`. Оба платформенных транспортных пакета v1.2.2 собраны, установлены и проверены на тестовых MODX 2.8.9-pl и MODX 3.2.4-pl. Результаты релиза 1.2.1 ниже сохранены как история.

## Исторические проверки версии 1.2.1

На момент выпуска v1.2.1 поддерживались обе версии MODX, а контракт содержал **192/192** серверных действия: 81 операцию чтения и 111 изменений. Это **исторические результаты 1.2.1**, а не текущий контракт 1.2.2. По сравнению с v1.1.0 линия 1.2.0 добавила 10 действий и защиту Runtime CAS/stale-state.

- модульное покрытие v1.2.1: **192/192**;
- MODX 3.2.4-pl: полный набор из 14 live-suite пройден в рамках исторической проверки v1.2.0; релиз v1.2.1 отдельно прошёл transport release-smoke;
- совместимость процессоров MODX 3: пройдена для 3.2.2-pl, 3.2.4-pl и текущей ветки 3.x (113 используемых processor files);
- MODX 2.8.9-pl: пройдены transport release-smoke, read parity для 81 действия и core/runtime mutation matrix; положительный MIGX lifecycle пропущен, поскольку MIGX на этом стенде не установлен;
- Runtime CAS/stale-state smoke пройден на обоих поддерживаемых поколениях MODX;
- положительный цикл MIGX mutations пройден 3/3 на MODX 3.
