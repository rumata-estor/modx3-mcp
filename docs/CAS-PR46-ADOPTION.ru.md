# Интеграция CAS по исходным значениям TV (PR #46) — подготовка MODX MCP 1.2.8

**Автор исходного исправления: [AgelxNash](https://github.com/AgelxNash).**

Источники: [оригинальный PR #40](https://github.com/rumata-estor/modx3-mcp/pull/40), [выделенный PR #46](https://github.com/rumata-estor/modx3-mcp/pull/46).

Изменения PR #46 перенесены через git cherry-pick; оригинальное авторство, дата и сообщение коммита сохранены средствами Git. Автор дополнительных тестов и интеграции не подменяет автора исходного исправления.

## Принято из PR #46

- CAS expected_tvs сравнивается с исходным значением TV (getValue), а не с обработанным HTML из getTVValue.
- Чтение TV использует getTemplateVars с резервным механизмом.
- Повторно используются экземпляры TV; запись производится штатным setTVValue.
- Изменения охватывают MODX 2 и MODX 3, а также модульные реализации.

## Ограничения и правила приёмки

Это **тестовая ветка на базе 1.2.7**, а не выпущенный релиз 1.2.8. Номер опубликованного компонента не менялся.

В CI добавлены регрессия TV/CAS и отдельная проверка на временных установках MODX 2/3, включающая raw TV, @INHERIT, строгую ревизию, конфликт исходного значения, независимый readback и восстановление по новому CAS. Тест во временной среде запрещён вне GitHub Actions и не использует боевые сайты.

Нельзя считать исправленным весь CAS v2 только по результатам тестирования TV: отдельно требуют анализа атомарность фиксации site_revision, работа конкурентных запросов и совместимость с клиентами без _runtime_preconditions.

Нельзя сливать в main, публиковать пакет или устанавливать на рабочие сайты до успешных интеграционных тестов, ревью и отдельного решения о выпуске.
