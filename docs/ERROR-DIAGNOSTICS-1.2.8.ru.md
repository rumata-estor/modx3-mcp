# MODX MCP 1.2.8: понятные ошибки и диагностика

**Статус:** только тестовая ветка 1.2.8. Без публикации пакета, merge в main или изменений production.

## Что увидит пользователь

В ответе MCP-инструмента с `isError: true` клиент показывает на русском:

- действие и понятный заголовок;
- причину отказа, если она установлена;
- достоверный результат изменения: `not_applied`, `rolled_back`, `partial`, `unknown`, `completed`;
- конкретное безопасное дальнейшее действие и возможность повтора;
- стабильный код причины и идентификатор инцидента.

Например:

> Данные изменились после предыдущего чтения.
>
> Операция: update_element.
>
> Причина: Сохранённый снимок больше не совпадает с текущим состоянием.
>
> Результат: Изменения не внесены.
>
> Что делать: Прочитайте объект заново, сравните изменения и согласуйте новую запись.
>
> Код: STALE_STATE
>
> Номер диагностики: modxmcp_0123456789abcdef01234567

**Состояние `unknown` никогда не должно приводить к автоматическому повтору записи**. Сначала безопасное чтение объекта через MCP, затем новое согласованное решение. `rolled_back` можно сообщить только при доказанном откате; центральный обработчик не выдумывает откат, если об этом ничего не известно.

При успехе сервер возвращает `outcome=completed`, `operation_code=OPERATION_COMPLETED` и `message_ru`: завершение запроса подтверждено обработчиком MODX. Это **не** значит, что проведена независимая проверка результата чтением. Узлы Node MCP сохраняют первый блок JSON для старых клиентов; для успешных мутаций добавляется отдельный текстовый блок с этим уточнением.

## HTTP-контракт и совместимость

Существующие `success`, `error`, `data`, `caps`, HTTP-статусы и запреты доступа сохраняются. К ошибкам добавлены необязательные поля `code`, `error_id`, `message_ru`, `reason_ru`, `next_action_ru`, `outcome`, `retry_policy`.

Неизвестный старый текст ошибки приводится к безопасному `OPERATION_REFUSED`; его детали не включаются в новые сообщения. У старого PHP endpoint без расширенных полей Node распознаёт известные префиксы ошибок и сохраняет консервативное поведение. Для сетевого обрыва во время записи Node ставит `CONNECTION_FAILED`, `unknown`, `verify_before_retry`, не возобновляет запрос автоматически.

Проверки HTTPS, токена, IP, CAS, signed permit, а также выбор `401/403/400/500` не ослаблены. Необработанные исключения PHP, секреты, SQL, внутренние пути и тело HTTP-запроса не выдаются пользователю.

## Диагностика разработчика

При отказе PHP пишет в стандартный защищённый журнал MODX безопасную запись `[error_id] code, stage / action / HTTP status`; для внутренних исключений — также **класс**, но не текст исключения. Идентификатор позволяет связать ответ с записью.

При наличии доступа к группе `ops` инструмент `modx_read_error_log` принимает необязательный параметр `error_id` и ищет совпадение внутри уже существующего ограниченного чтения логов. При отсутствии строки нельзя делать вывод, что ошибки не было: журнал мог ротироваться или не входить в лимит сканирования. Доступ и маскирование секретов инструмента сохранены.

Ошибки Node до HTTP-ответа получают локальный `mcpnode_...` и безопасную строку в stderr (`code`, `operation`, `stage`, `network_code`, `outcome`); они **не появятся автоматически** в журнале PHP. Разработчик ищет их в логах MCP-хоста/Node, если хост сохраняет stderr. Сетевой код (например, `ECONNRESET`) — не доказанная причина отказа MODX.

Новый клиент не завершает stdio-процесс из-за отсутствия `MODX_MCP_SITE_URL` / `MODX_MCP_TOKEN` или неверного URL; он возвращает `CLIENT_CONFIG_INVALID` при вызове инструмента. Однако если сам процесс Node аварийно завершился до установления MCP-транспорта, платформа может по-прежнему показать `Connection closed`; отправить прикладную ошибку после смерти процесса невозможно. Для этого случая предусмотрено только безопасное сообщение о запуске в stderr, где оно доступно.

## Критерии приёмки

- Ошибки CAS, доступа, отказа записи, неизвестного результата, HTTP 401/403/400/500, сетевого тайм-аута и некорректной конфигурации дают понятное действие на русском.
- Все явно известные запреты до записи = `not_applied`; всё, что может иметь побочный эффект без подтверждения = `unknown`.
- Ни ответ, ни stderr не содержат непроверенного текста исключения или токена.
- HTTP API и первый блок JSON MCP-результата сохраняют обратную совместимость.
- Фильтрация журнала по `error_id` не отключает проверку прав и не читает журнал без ограничений.
- CI, матрица disposable MODX2/3 и настоящее обновление 1.2.7 → тестовая 1.2.8 остаются обязательными.
