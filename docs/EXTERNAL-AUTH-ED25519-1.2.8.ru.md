# MODX MCP 1.2.8 — независимая авторизация по Ed25519 (подготовка)

**Текущий статус: криптографический формат и автономные тесты; авторизация НЕ подключена к HTTP API или диспетчеру, записывающие операции пока не требуют permit.** Не следует ставить или включать защищённый режим на сайте.

## Модель доверия

- Внешний доверенный Controller подписывает конкретное разрешение своим приватным ключом Ed25519; секрет не попадает на сервер MODX.
- MODX MCP сохраняет только публичный ключ доверенного контроллера, привязанный к конкретной инсталляции. API-токен HTTP остаётся независимым первым уровнем аутентификации.
- Подписываемые поля имеют строго фиксированный порядок, версии и кодировку: audience, site_id, contour, action, element_type, SHA-256 точного HTTP-запроса, случайный nonce, issued_at и expires_at. Нельзя подменить имя операции, сайт или параметры.
- Сервер получает ожидаемую аудиторию, site_id, contour и публичный ключ из собственной защищённой конфигурации; доверять таким полям в теле запроса запрещено.
- Сначала сверяется идентичность клиента и криптографическая подпись, затем текущий CAS и полномочия; только после этого допускается выполнение.
- Сам по себе IndependentPermitV1::verifyCryptographicClaims — только офлайн-проверка подписи, не выдаёт право на изменение. Не подключать его к API напрямую.

## Предупреждение о старом эксперименте

В изолированной ветке защиты 2026-11-21 был формат permit на HMAC с одним секретным ключом у проверяющего и подписывающего. Он не обеспечивает желаемое разделение ключей; исходный эксперимент не переносился в 1.2.8. Авторизация старым HMAC/permit-v1 или v2 без явной миграции запрещена.

## Проверено

Файл _build/test.permit-ed25519-interop.cjs подписывает данные в изолированном Node.js, передаёт PHP только подпись, публичный ключ и поля, затем _build/test.permit-ed25519-verify.php проверяет 14 сценариев: действительная подпись, подделка подписи или публичного ключа, смена сайта/операции/типа/nonce/запроса, истечение/ранний срок действия, добавление/удаление поля, неподдерживаемая версия.

Тесты должны проходить на PHP 7.4/8.2 с ext-sodium. Если libsodium отсутствует — fail closed, без перехода на HMAC.

В CI дополнительно предусмотрен тест одноразовости на MariaDB: _build/test.ci-permit-nonce-ledger.php. Он создаёт и удаляет отдельную временную таблицу nonce, не изменяет данные сайта. Резервирование и воспроизведение nonce выполняются через внутренний авторизационный примитив, а не обходят бизнес-операции MCP. Наличие успешно проверенного примитива не означает, что он уже участвует в обработке HTTP-запросов.

## Нельзя включать в работу до завершения

1. Replay-защита: добавлен и проверяется отдельно примитив PermitNonceLedger на уникальном индексе InnoDB. Два независимых PHP-процесса с одним nonce должны давать одного победителя; запись nonce должна сохраняться при ошибке следующей операции. **Это пока только отдельно тестируемый примитив:** необходимо предусмотреть таблицу и миграцию в установщике, создать выделенное соединение (не транзакцию самого MODX), интегрировать резервирование nonce после подписи и до запуска операции, проверить сбои хранилища, восстановление и сквозной HTTP replay.
2. Защита хранилища публичных ключей и политики: недопустимы клиентские значения trusted, разрешения неизвестного ключа, снятие защиты вследствие сбоя загрузки или ошибки прав.
3. Привязка к реальному HTTP API: сырой байтовый запрос, подпись и CAS должны проверяться до выполнения любой мутации. При включённом защищённом режиме прямой вызов processRequest() не должен обходить контроль.
4. Полная авторизация: разрешённое действие, ресурс, целевые поля, подтверждение опасных команд, срок и уникальный запрос, контур, конкретный сайт.
5. Противодействие обходу: запрет на replay, forged MAC/ключ, кросс-сайт, другой контур, другой метод, изменённый JSON, пропущенные предусловия и fallback.
6. Сквозная проверка HTTP на одноразовых MODX 2/3, затем отдельное одобренное испытание с Controller/Executor в тестовом Site Agent.

До выполнения пунктов 1–6 мы не называем независимую авторизацию реализованной. Никаких изменений в main, стабильной 1.2.7, на сайтах, ключах или боевом Controller.


## Промежуточная интеграция в тестовой ветке (без включения на сайтах)

В тестовой ветке реализован защищённый маршрут в processRequest() для MODX 2/3: если фактическое значение external_authorization_required в базе равно 1, каждая мутация требует Ed25519 permit и атомарно расходует nonce до запуска бизнес-операции, под общей блокировкой CAS. Проверка не ограничена одним HTTP-путём, поэтому прямой вызов обработчика без permit должен отклоняться. Если таблица nonce отсутствует, ключ не настроен, источник проверяемого запроса неизвестен или соединение не установлено, запись отклоняется (fail-closed).

Встроено извлечение X-ModxMCP-Permit из HTTP и криптографическая привязка к точному телу запроса. Конфигурация аудитории, сайта, контура и публичного ключа берётся из настроек MODX (не из клиента), при этом прямые MCP-изменения настроек modxmcp.* запрещены. Режим по умолчанию выключен; приватный ключ никогда не генерируется на стороне компонента.

Отдельный установщик _build/provision.protected-nonce-ledger.php требует явного административного подтверждения и создаёт только таблицу авторизационных nonce; он не вызывается автоматически при обычной установке/обновлении. В CI разрешён исключительно на одноразовом MODX. Настройки добавлены и в обычный transport, и в headless installer.

Тест _build/test.ci-protected-auth.php на одноразовых MODX должен доказать создание/изменение/удаление с подписанным запросом, отказ без подписи, отказ при повторном использовании nonce, изменении тела, подмене сайта/операции/типа и запрет смены защитных настроек через MCP. Затем отдельная реальная HTTP-проверка и совместимость с Controller/Executor. Пока тесты интеграции не прошли, защищённый режим не признаётся готовым и не включается.
