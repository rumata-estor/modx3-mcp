# Восстановление после частичных внешних эффектов — MODX MCP 1.2.8

> Статус: **тестовая ветка**. Документ описывает подтверждаемые сценарии и
> действия оператора; он **не является гарантией автоматического отката**.
> Ничего из перечисленного не разрешает устанавливать пакеты на production
> без отдельного решения.

## Что гарантирует диспетчер

1. До опасного действия требуется CAS-предусловие; отказ резервирования
   `site_revision` прекращает выполнение до вызова внешнего процессора.
2. Исключение, ошибка или отсутствие ответа **после начала** установки,
   удаления пакета или выполнения произвольного процессора возвращает
   `MUTATION_OUTCOME_UNCERTAIN`. Исходный текст исключения, включая секреты,
   не передаётся клиенту.
3. **Это не rollback:** скачанный архив, установленная настройка, файл,
   выполненный плагин, отправленная почта или сетевой запрос могли сохраниться.
   Увеличение ревизии после начала внешнего эффекта не подтверждает его успех.
4. Повтор со старым CAS блокируется; **повтор с новым CAS не становится
   автоматически идемпотентным**. Автоматически повторять такую мутацию нельзя.

## Проверки

- `_build/test.package-uncertain-result.php` и
  `_build/test.processor-master-switch.php`: граничные и негативные
  автономные сценарии.
- `_build/test.ci-external-partial-effects.php`: установленный MODX 2/3,
  реальная запись файлов, имитированный аварийный диспетчер. Это **не**
  настоящая установка стороннего транспортного пакета.
- `_build/test.ci-package-real-uncertain.php`: собственный одноразовый
  MODX transport; настоящий `modTransportPackage::install()/uninstall()`,
  фиктивная потеря ответа **после** native-операции; независимое чтение
  сохранённой системной настройки и состояния пакета.
- `_build/test.ci-processor-plugin-effects.php`: настоящий временный MODX
  plugin/event, файловый эффект до ошибки внешнего процессора. Запуск
  процессора здесь инструментирован; сценарий не представляет все плагины.

## Порядок при `MUTATION_OUTCOME_UNCERTAIN`

**Немедленно остановить автоматические повторы.** Зафиксировать команду,
идентичность пакета или процессора, время, действие, ID операции, состояние
CAS/nonce и error_id (если есть). Ни успешный HTTP-ответ, ни увеличение
`site_revision` не являются доказательством завершённого изменения.

Для установки пакета отдельно проверить конкретную **signature** в
`modTransportPackage` через разрешённый административный маршрут,
наличие архива в `core/packages` и изменения его транспортных vehicles:
файлы, namespace, настройки, меню, события и результаты PHP-resolvers.
`list_installed_components` перечисляет файловые каталоги — это
**не авторитетное доказательство установленного/удалённого пакета**.

Для удаления пакета проверить состояние package record **и** сохранность
артефактов/настроек. Успешный `uninstall()` не гарантирует удаления
данных, которые пакет сохраняет по своим правилам; нельзя удалять чужие
остатки по одному совпадению имени каталога.

Для `run_processor` требуется заранее известная карта ожидаемых
последствий **конкретного** пути: изменённые MODX-объекты, плагины,
файлы, сообщения, вебхуки. Проверить результаты независимо через
разрешённое чтение MCP/Manager и, если необходимо, внешний сервис.
Если проверка неполная, исход остаётся **UNKNOWN**, а повтор запрещён.

## Решение о повторе

| Наблюдение | Действие |
| --- | --- |
| Подтверждён полный успех | Не повторять; зафиксировать readback |
| Подтверждён отказ до **любого** эффекта | Повтор допустим только с новым CAS, новой авторизацией и явным разрешением оператора |
| Обнаружен частичный эффект | Не повторять; выполнить план компенсации именно этого пакета/процессора |
| Нельзя определить исход | Не повторять; ручной разбор, сохранение доказательств |

**Не выполнять универсальный «откат» внешних действий.**
Для отправленных email, событий и вебхуков компенсирующей транзакции
может не существовать. Ручное восстановление обязано проверять права,
зависимости и наличие чужих изменений.

## Что эти тесты не закрывают

- Crash/kill в произвольной инструкции чужого `resolver`, повторяемость
  сетевых запросов и таймауты настоящих сторонних провайдеров.
- Идемпотентность по `operation_id` для неизвестных сторонних эффектов;
  такого универсального журнала здесь не добавляли.
- Распределённые гонки с MODX Manager, другими узлами и посторонними
  локальными процессами.
- Гарантированную компенсацию отправленной почты, HTTP-запросов,
  пользовательских плагинов и любых неучтённых файлов.

**Критерий релизного решения:** отдельная политика допустимых
пакетов/процессоров и восстановления для каждого семейства эффектов.
Зелёный CI доказывает конкретные сценарии, а не универсальную
атомарность всех внешних операций.
