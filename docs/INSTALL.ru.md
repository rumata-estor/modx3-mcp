# Установка и подключение MODX MCP

[English](INSTALL.md) | **Русский** · [Возможности](CAPABILITIES.ru.md) · [Справочник API](API.ru.md) · [Безопасность](SECURITY.ru.md)

MODX MCP позволяет подключить ИИ-клиент к сайту на **MODX Revolution 2.8.x или 3.x** через стандартный протокол **MCP (Model Context Protocol)**. Для обычной работы нужны транспортный пакет на сайте, Node.js 18+ на компьютере или сервере, где запускается MCP-клиент, и поддерживающая MCP программа.

**Отдельный сервер управления или сторонний агентский рантайм не требуется.** Компонент на сайте отвечает за HTTP API, а локальный процесс `modx-mcp` обеспечивает стандартный интерфейс MCP через `stdio`. Серверный PHP endpoint — не самостоятельный MCP-stdio-процесс.

## 1. Выберите пакет для своей версии MODX

- **MODX 2.8.x**: `modx2mcp-1.2.0-pl.transport.zip`.
- **MODX 3.x**: `modx3mcp-1.2.0-pl.transport.zip`.

Транспортные пакеты соответствуют разным версиям платформы, но используют общий набор публичных команд и один Node.js MCP-клиент. Актуальные файлы ищите в [релизах GitHub](https://github.com/rumata-estor/modx3-mcp/releases); при необходимости используйте соответствующий источник пакетов MODX.

**Особенность MODX 2.** Если установлен старый пакет с именем `modxmcp`, для перехода на новую идентичность `modx2mcp` рекомендуется сначала удалить прежний пакет через менеджер пакетов, затем установить `modx2mcp`. Такая чистая переустановка удаляет старые настройки `modxmcp.*`, включая токен; сохраните нужные сведения заранее и после установки обновите настройки клиента. Обычные последующие обновления пакета `modx2mcp` сохраняют существующий токен.

## 2. Установите пакет на сайт

1. Откройте менеджер MODX с административными правами.
2. В менеджере пакетов загрузите транспортный ZIP для нужной версии MODX и выполните установку.
3. Откройте раздел дополнения **MODX MCP** либо системные настройки с пространством имён `modxmcp`.
4. Убедитесь, что `modxmcp.enabled` включена и создан `modxmcp.api_token`.
5. Скопируйте токен в конфигурацию **своего MCP-клиента**. Это секретный ключ; не публикуйте его в репозитории, сообщениях и журнале ошибок.

При штатной установке токен генерируется автоматически, если его ещё нет. Существующий токен не должен автоматически заменяться при обычном обновлении.

## 3. Найдите адрес API сайта

При стандартном размещении:

```text
https://example.com/assets/components/modxmcp/api.php
```

Замените `example.com` доменом сайта и уточните фактический путь, если установку выполняли нестандартно. Для безопасной эксплуатации используйте **HTTPS**.

`GET` по адресу API возвращает ограниченные сведения о компоненте и версии — это проверка доступности, а не проверка авторизации. Для выполнения действий API использует `POST`, заголовок `X-MCP-Token` и JSON.

## 4. Настройте MCP-клиент

На компьютере или сервере, где работает ваш ИИ-клиент, нужен **Node.js 18+** и `npx`/npm. Укажите локальный MCP-сервер в конфигурации выбранного приложения. Пример общего формата (место размещения и структура конфигурации могут отличаться у разных клиентов):

```json
{
  "mcpServers": {
    "modx": {
      "command": "npx",
      "args": [
        "-y",
        "github:rumata-estor/modx3-mcp#v1.2.0"
      ],
      "env": {
        "MODX_MCP_SITE_URL": "https://example.com/assets/components/modxmcp/api.php",
        "MODX_MCP_TOKEN": "СЕКРЕТНЫЙ_ТОКЕН_ЭТОГО_САЙТА"
      }
    }
  }
}
```

Здесь `MODX_MCP_SITE_URL` — адрес PHP endpoint, `MODX_MCP_TOKEN` — токен именно этого сайта. На рабочих системах закрепляйте **проверенный релизный тег**, а не `main`. Конкретный интерфейс настройки зависит от клиента; убедитесь, что он поддерживает запуск MCP-сервера через `stdio`.

## 5. Проверьте подключение

После перезапуска или обновления списка MCP-серверов убедитесь, что у клиента появился сервер `modx` и доступные инструменты с префиксом `modx_`. Начните с запросов только для чтения:

```text
Покажи версию MODX и обзор структуры сайта. Ничего не изменяй.
```

Для этого клиент может использовать `modx_system_info` и `modx_project_overview`. Количество видимых инструментов может быть меньше 191: зависит от установленных дополнений и отключённых групп возможностей.

## 6. Дополнительные настройки безопасности

Для открытых и рабочих сайтов проверьте настройки:

| Настройка | Назначение |
| --- | --- |
| `modxmcp.enabled` | Общий выключатель API. |
| `modxmcp.api_token` | Секретный ключ доступа. |
| `modxmcp.require_https` | Требовать HTTPS; штатное значение — включено. |
| `modxmcp.allowed_ips` | Необязательный список разрешённых адресов и IPv4 CIDR; пустое значение не ограничивает адреса. |
| `modxmcp.trust_proxy_https` | Доверять признаку HTTPS от обратного прокси только при корректной инфраструктуре. |
| `modxmcp.disabled_groups` | Выключать некоторые группы функций; **не заменяет разграничение полномочий**. |
| `modxmcp.allow_run_processor` | Отдельное разрешение на прямой вызов процессоров MODX; штатно выключено. |
| `modxmcp.max_payload_bytes` | Ограничение размера запросов. |
| `modxmcp.debug` | Подробности ошибок; на рабочих сайтах оставляйте выключенным. |

**Внимание:** после успешной авторизации действия выполняются от имени служебного пользователя MODX с правами `sudo`. Компрометация токена может означать полный административный доступ, включая изменение PHP-кода через элементы сайта. См. [модель безопасности](SECURITY.ru.md).

## Если что-то не работает

| Признак | Что проверить |
| --- | --- |
| MCP-сервер не запускается | Node.js 18+, `npx`, доступность пакета и правильность конфигурации конкретного клиента. |
| `401 Unauthorized` | Совпадают ли `MODX_MCP_TOKEN` и `modxmcp.api_token`; не был ли токен перевыпущен. |
| `403` | `modxmcp.enabled`, HTTPS, настройки доверенного прокси, разрешённый IP. |
| `404` | Путь до `api.php`, корректность установки компонента и правила веб-сервера. |
| `413` | Превышен лимит `modxmcp.max_payload_bytes`. |
| Инструмента нет в списке | Версии клиента/сервера, `modxmcp.disabled_groups`, наличие нужного дополнения. |
| `500` | Журнал ошибок MODX и `error_id`; отключите подробный вывод ошибок на рабочем сайте. |

При прямой проверке HTTP API не передавайте токен в URL: используйте заголовок `X-MCP-Token` и защищённое соединение.
