# Встановлення та підключення MODX MCP

[English](INSTALL.md) · [Русский](INSTALL.ru.md) · [Español](INSTALL.es.md) · [Deutsch](INSTALL.de.md) · [Français](INSTALL.fr.md) · [Українська](INSTALL.uk.md) · [Қазақша](INSTALL.kk.md) · [Nederlands](INSTALL.nl.md) · [Polski](INSTALL.pl.md) · [Можливості](CAPABILITIES.uk.md) · [Довідник API](API.uk.md) · [Безпека](SECURITY.uk.md)

MODX MCP дає змогу стандартному ШІ-клієнту, сумісному з MCP, працювати з **MODX Revolution 2.8.x і 3.x**. Для звичайного встановлення потрібні транспортний пакет MODX, **Node.js 18+** на комп’ютері, де працює ваш MCP-клієнт, і застосунок, здатний запускати MCP-сервери через **stdio**.

**Окремий сервер оркестрації не потрібен.** Компонент MODX розміщує HTTP API на вашому сайті; локальний процес `modx-mcp` надає MCP-клієнтам доступ до цього API через `stdio`. Сама кінцева точка PHP не є безпосереднім MCP-сервером stdio.

## 1. Виберіть пакет MODX

- **MODX 2.8.x:** `modx2mcp-1.2.5-pl.transport.zip`.
- **MODX 3.x:** `modx3mcp-1.2.5-pl.transport.zip`.

> **Статус:** вихідний код 1.2.5 підготовлено, але транспортні ZIP ще не опубліковано. Для встановлення використовуйте [версію 1.2.4](https://github.com/rumata-estor/modx3-mcp/releases/tag/v1.2.4).

Обидва варіанти використовують однаковий публічний контракт інструментів і клієнт Node.js. Завантажте відповідний пакет із [GitHub Releases](https://github.com/rumata-estor/modx3-mcp/releases) або від підтримуваного постачальника пакетів MODX.

**Наявні інсталяції MODX 2:** під час переходу зі старої ідентичності пакета `modxmcp` на `modx2mcp` рекомендовано повністю видалити старий пакет, а потім установити `modx2mcp`. Повне видалення прибирає старі налаштування `modxmcp.*` і токен API. За потреби збережіть відповідну конфігурацію та після переходу оновіть облікові дані клієнта. Подальші звичайні оновлення `modx2mcp` зберігають поточний токен.

### Панель компонента в менеджері

У розділі **Компоненти → MODX MCP** скопіюйте URL API, відкрийте для перегляду чи скопіюйте наявний токен лише за наявності у вашого облікового запису менеджера дозволу **settings**, увімкніть або вимкніть необов’язкові групи можливостей і налаштуйте **Auto-static** / **Audit log**. Зміни налаштувань і можливостей набувають чинності лише після натискання відповідних кнопок збереження. **Граф залежностей** доступний за посиланням на граф; його полотно масштабується колесом миші, а навколишня панель прокручується для перегляду фільтрів і подробиць. **Повторне створення токена** робить недійсними облікові дані всіх наявних клієнтів; звичайні оновлення пакета цього не роблять. Напис «MCP увімкнено» на сторінці не є перевіркою поточного підключення конкретного клієнта.

## 2. Установіть транспортний пакет

1. Увійдіть до менеджера MODX під обліковим записом, якому дозволено встановлювати пакети.
2. Відкрийте керування пакетами, завантажте транспортний ZIP для вашої основної версії MODX і встановіть його.
3. Відкрийте компонент MODX MCP або системні налаштування з простором імен `modxmcp`.
4. Перевірте `modxmcp.api_token` і мережеві обмеження. Нові інсталяції починають із `modxmcp.enabled = 0`; увімкніть компонент вручну після захисту доступу.
5. Скопіюйте токен до **конфігурації MCP-клієнта**. Ставтеся до нього як до секрету, ніколи не використовуйте як публічний приклад.

Інсталятор створює криптографічно випадковий токен, якщо налаштування порожнє. Звичайне оновлення зберігає наявний токен.

## 3. Визначте кінцеву точку сайту

Стандартний URL:

```text
https://example.com/assets/components/modxmcp/api.php
```

Використовуйте власний домен; у нестандартних розгортаннях фактичний шлях може відрізнятися. **HTTPS** рекомендовано, і за замовчуванням він обов’язковий.

`GET` повертає обмежену відповідь про працездатність і версію компонента без автентифікації. Адміністративні запити використовують JSON `POST` із `X-MCP-Token`.

## 4. Налаштуйте хост MCP

На комп’ютері, де працює ваш ШІ-застосунок, установіть **Node.js 18+** із npm/`npx`. Додайте MCP-сервер до конфігурації хоста (розташування та підтримувана структура конфігурації залежать від застосунку):

```json
{
  "mcpServers": {
    "modx": {
      "command": "npx",
      "args": [
        "-y",
        "github:rumata-estor/modx3-mcp#v1.2.4"
      ],
      "env": {
        "MODX_MCP_SITE_URL": "https://example.com/assets/components/modxmcp/api.php",
        "MODX_MCP_TOKEN": "YOUR_SITE_PRIVATE_TOKEN"
      }
    }
  }
}
```

`MODX_MCP_SITE_URL` — кінцева точка HTTP API на PHP. `MODX_MCP_TOKEN` — токен саме цього сайту. У production-системах фіксуйте **опублікований тег випуску**, а не відстежуйте `main`. Переконайтеся, що ваш хост підтримує запуск локального MCP-сервера через `stdio`.

## 5. Перевірте підключення

Перезапустіть інтеграцію MCP або оновіть список серверів хоста. Знайдіть сервер `modx` та інструменти з префіксом `modx_`. Почніть із запиту лише на читання, наприклад:

```text
Show the MODX version and an overview of the site structure. Make no changes.
```

Для цього можуть використовуватися `modx_system_info` і `modx_project_overview`. Ваш хост може показувати менше ніж 192 інструменти залежно від збірки сервера, вимкнених груп і встановлених доповнень.

[Повний довідник системних налаштувань](SETTINGS.uk.md) описує **всі 16 налаштувань**, їхні значення за замовчуванням, поведінку та наслідки для безпеки.

## 6. Налаштування безпеки, які слід перевірити

| Налаштування | Значення |
| --- | --- |
| `modxmcp.enabled` | Увімкнення або вимкнення API. |
| `modxmcp.api_token` | Секретні облікові дані API. |
| `modxmcp.require_https` | Вимога HTTPS; увімкнено за замовчуванням. |
| `modxmcp.allowed_ips` | Необов’язковий список дозволених IP-адрес і діапазонів IPv4 CIDR; порожнє значення дозволяє будь-яке джерело. |
| `modxmcp.trust_proxy_https` | Довіра до заголовка HTTPS зворотного проксі лише за правильно налаштованого проксі. |
| `modxmcp.disabled_groups` | Вимкнення окремих сімейств інструментів; **не є межею рольового контролю доступу**. |
| `modxmcp.allow_run_processor` | Дозвіл прямого виклику процесорів MODX; вимкнено за замовчуванням. |
| `modxmcp.max_payload_bytes` | Обмеження розміру запиту. |
| `modxmcp.debug` | Подробиці помилок; у production залишайте вимкненим. |

**Важливо:** запити виконуються від імені службового користувача MODX із привілеями `sudo`. Розголошення дійсного токена може дозволити адміністративні зміни та модифікацію виконуваного PHP в елементах. Прочитайте [посібник із безпеки](SECURITY.uk.md).

## Усунення несправностей

| Симптом | Що перевірити |
| --- | --- |
| MCP-сервер не запускається | Node.js 18+, `npx`, отримання пакета та конфігурацію хоста. |
| `401 Unauthorized` | `MODX_MCP_TOKEN` має збігатися з `modxmcp.api_token`; перевірте, чи не було ротації токена. |
| `403` | Налаштування ввімкнення компонента, HTTPS, конфігурацію зворотного проксі та дозволену IP-адресу. |
| `404` | Шлях кінцевої точки, встановлення компонента та маршрутизацію вебсервера. |
| `413` | Запит перевищив `modxmcp.max_payload_bytes`. |
| Інструмент недоступний | Версії клієнта й сервера, вимкнені групи, наявність потрібного доповнення. |
| `500` | Журнали помилок MODX і `error_id`; не показуйте налагоджувальні повідомлення публічно. |

Не додавайте токени API до рядків запиту чи звітів про проблеми. Власні HTTP-клієнти мають передавати `X-MCP-Token` через TLS.
