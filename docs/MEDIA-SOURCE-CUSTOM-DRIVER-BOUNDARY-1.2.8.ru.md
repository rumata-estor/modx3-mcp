# MODX MCP 1.2.8 — нестандартные Media Source и файловая граница

**Статус:** кандидат в тестовую ветку. Установленные сайты и пакеты не изменены.

## Найденные проблемы

1. `read_media_source_file` и `list_media_source_files` вызывали
   `rootPath()`, `scandir()` и `file_get_contents()` непосредственно.
   Для пользовательских и удалённых драйверов это обходило контракт
   драйвера (включая проверки доступа, виртуальные пути и remote storage).
   Сам факт локального `basePath` в `properties` не означает, что
   исходный драйвер разрешил чтение локального файла.
2. `delete_media_folder` на MODX 2 превращал путь в абсолютный
   хостовый путь перед `removeContainer()` **для всех** драйверов.
   Нестандартный драйвер ожидает ключ/путь относительно собственного
   virtual root, и абсолютный путь может означать другую цель.

## Принятое ограниченное исправление

- Прямые PHP filesystem-read/list допускаются только для штатного
  `sources.modFileMediaSource` (или `modFileMediaSource`) MODX 2 и
  `MODX\\Revolution\\Sources\\modFileMediaSource` MODX 3.
  Для этих источников **сохраняется** существующий переключатель
  `modxmcp.allow_root_filesystem_read` и проверка realpath/root.
- Для custom/remote-драйверов `read_media_source_file` и
  `list_media_source_files` дают безопасную понятную ошибку,
  **не вычисляя и не открывая локальный файл**. Поддержку remote-read
  можно добавить отдельно на основе **штатного API драйвера** и его
  проверки доступа, а не через локальную файловую систему.
- `delete_media_folder` преобразует путь в абсолютный только
  для стандартного локального MODX 2 Media Source. Для custom/remote
  драйверов на обеих платформах передаёт source-relative путь.
- `create/update/delete/rename_media_file` и создание папки
  продолжают делегировать действия самому драйверу, не заменяются
  независимыми PHP-файловыми операциями.
- Никаких Python, Node, PHP-расширений или новых обязательных
  зависимостей не добавлено.

## Совместимость и ограничения

Изменение **намеренно ограничивает** ранее существовавший прямой read/list
для кастомных драйверов, даже если они объявляли локальный basePath.
Этот небезопасный путь не должен сохраняться автоматически. В отличие
от чтения, пользовательские мутации продолжают опираться на сам драйвер,
поэтому безопасность нестандартных реализаций (например, S3, SFTP,
интеграционные файловые менеджеры) зависит от их собственного API.

Ограничения PHP `realpath`/TOCTOU при атакующем с правом переименовать
родительскую директорию **не устраняются** данным PR. Нельзя обещать
абсолютное отсутствие race без descriptor-anchored API.

## Проверки

- `_build/test.media-custom-driver-boundary.php`: имитация remote-
  драйвера с `basePath`, указывающим на локальный secret, в MODX 2/3.
  Read/list отклоняются без доступа к файлу, delete получает
  source-relative путь, локальные файловые источники сохраняют read/list
  и соответствующий переключатель; прежний MODX2-путь сохранён.
- `_build/test.ci-custom-media-boundary.php`: реальная disposable
  установка MODX 2/3, существующий стандартный Media Source id=1,
  запрет чтения без переключателя и разрешённые list/bounded-read
  установленного компонента через MODX MCP. Никакой записи в production.
- Прежние `test.media-path-boundaries.php` и
  `test.media-folder-path-contract.php` остаются обязательными.

**Release gate:** перед 1.2.8 получить перечень фактически поддерживаемых
сторонних драйверов и покрыть их read/list через официальные API
индивидуальными тестами. Если у клиента раньше работал кастомный
локальный источник, ему будет возвращена диагностическая ошибка вместо
небезопасного обхода — это изменение публичного поведения должно
быть явно описано в релизных примечаниях.
