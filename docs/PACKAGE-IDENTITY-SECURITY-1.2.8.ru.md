# Проверка идентичности транспортного пакета в 1.2.8

Дата: 22 ноября 2026. Область: `install_package`, только тестовый контур PR #49.

Обнаружена опасная неоднозначность: прежняя реализация при отсутствии точного имени выбирала первый результат поиска MODX-провайдера. Запрос `package=fixture` мог установить чужой пакет при поисковой выдаче с похожим именем. При указанном `target_signature` проверялась подпись без проверки имени; после загрузки код доверял иной подписи в `getObject()` и мог передать её в `workspace/packages/install`.

Изменение: только точное совпадение имени пакета и, если указана, выбранной подписи допускает стадию загрузки. Подпись, фактически возвращённая загрузчиком, должна совпасть с выбранной; при несовпадении установка **не вызывается**, возвращается `MUTATION_OUTCOME_UNCERTAIN` (загрузка уже могла оставить файлы). Неоднозначный результат поиска отвергается до скачивания.

Тест `_build/test.package-uncertain-result.php` включает ложные ответы провайдера, ошибочную подпись загрузчика, исключения и неполные ответы. Никакие реальные транспортные пакеты не скачиваются и не устанавливаются; проверяется именно безопасный диспетчерский контракт. Ограничения: криптографическая проверка целостности скачанного transport-архива не является предметом данной проверки, как и восстановление после частичной установки; это отдельные задачи аудита.
