# Неполный анализ зависимостей: совместимость с существующими установками

## Дефект и границы

На существующем тестовом MODX 3.2.4 с Beta 5 операции `find_usages`, `dependency_graph` и `delete_element` с `dry_run:true` возвращали OPERATION_REFUSED. Тестовый чанк 136 был успешно создан и обновлён, но удаление остановлено на предпросмотре. Воспроизведён такой же сценарий на одноразовых MODX 2 и 3 с установленным исходным Beta 5 (14813df301dbeafc3085067f98ed8759e042a6aa), содержащим статический элемент с путём за пределами разрешённой директории. Конкретный проблемный элемент существующего сайта ещё предстоит идентифицировать по новым диагностическим данным.

## Контракт

- `search_code` и `find_usages` возвращают найденные совпадения, `analysis_complete`, `limit_reached`, `unavailable_count`, `unavailable_elements` (не более 100 записей) и предупреждение. Запись недоступного элемента содержит только тип, ID и разрешённый диагностический код. Содержимое, сырой текст исключения и путь запрещённого файла не выдаются.
- `dependency_graph` сохраняет доступные узлы и связи; `analysis_complete=false` означает неполное покрытие статического содержимого. Списки потенциально неиспользуемых элементов скрываются, `orphans_verified=false`; интерфейс не представляет отсутствие найденных связей как установленный факт. `truncated` по-прежнему означает усечённый вывод графа.
- Для массовой замены используется строгий поиск. Недоступный источник не пропускается при планировании массовой записи. Удаление элемента при неполном анализе отклоняется до резервирования CAS-ревизии; повторная проверка выполняется перед вызовом процессора. Предпросмотр не изменяет данные и ревизию, но возвращает предупреждение. Удаление ресурсов и категорий сохраняет свои отдельные проверки.
- Проверки границ `core/elements`, запрещённых путей, симлинков, hardlink и выбранного режима static I/O не ослабляются. Отсутствующий файл не подменяется содержимым старого DB-поля при анализе. Диагностические коды позволяют администратору найти объект и восстановить его корректную конфигурацию штатными средствами MODX. Не следует отключать защиту или удалять неизвестный статический файл для очистки предупреждения.
- `analysis_complete=true` означает покрытие доступных источников в пределах возможностей анализа, а не математическое доказательство отсутствия зависимостей. Динамические имена, произвольные вызовы PHP, сторонние таблицы, изменения вне MCP и ограничения portable filesystem I/O остаются ограничениями. CAS не заменяет анализ зависимостей и независимую авторизацию.

## Подтверждённые испытания

- Lifecycle run 45368195687: три матрицы MODX 2.8.9/3.2.4 с исходными пакетами 1.2.7/1.2.4. Успешно воспроизведены недоступные статические источники (внешний симлинк, hardlink, отсутствующий и внешний файл), сохранены доступные совпадения, подтверждены неполные графы и запрет удаления без расходования ревизии. После устранения тестовых метаданных безопасное удаление восстановлено. Пройдены существующие проверки 116 обязательных CAS-операций и транспортного жизненного цикла.
- Upgrade run 45368532696: исходный Beta 5 на MODX 2.8.9 и 3.2.4 воспроизвёл три отказа. Обновление тестовым транспортом 1.2.8-beta6 сохранило API token, enabled, CAS revision и целевой объект. После обновления частичный результат, отказ удаления и массовой замены, неизменность внешнего файла, восстановление полного анализа и удаление прошли (11+23 утверждения на каждой платформе). Это тестовые Actions-артефакты, не опубликованный релиз.
- Site Agent: ветка fix/modxmcp-beta5-cas-20261124, 143e904, принимает новый coverage-контракт; частичный/усечённый результат считается неподтверждённым влиянием. Локальная регрессия и предыдущий Beta 5 TLS interop run 45368302938 успешны.

## Следующий шаг на тестовом сайте

Установить проверенный тестовый транспорт поверх Beta 5, не деинсталлируя старую версию и не меняя настройки безопасности. Перед установкой администратор обеспечивает резервную копию тестового сайта. После обновления прочитать диагностику и установить конкретные ID недоступных элементов; проверить их конфигурацию, затем повторить защищённый dry-run и удаление чанка 136. Пока это не сделано, полный цикл на существующем сайте не считается завершённым. Production не затрагивался.
