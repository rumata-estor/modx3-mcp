## Дополнительный аудит Beta 3 — 24.11.2026

**Статус: NO-GO до приёмки исправлений.** Независимое ревью подтверждает два дефекта обратной совместимости именно в Beta 3: существующий static-файл в portable неожиданно требовал Python/`proc_open` (B3-01); обычный локальный Media Source внутри `assets_path` блокировался настройкой `modxmcp.allow_root_filesystem_read=0` (B3-02).

Подготовлен [Draft PR #186](https://github.com/rumata-estor/modx3-mcp/pull/186) от текущего SHA `5ff5d9c`: для статических файлов — PHP-only update **того же inode** (без переустановки пакетов/драйверов и потери ACL/xattrs от rename), для Media Sources — каноническая граница внутри assets без открытия site root. Изменения ещё не приняты. Перед новой публичной Beta потребуются зелёный CI, MODX2/3 disposable, реальный upgrade с 1.2.7 и отдельная проверка на PHP с отключёнными функциями запуска процессов. Не переименовывать старую Beta 3; собрать новую Beta с новым номером и SHA256 после приёмки.

**Остаточный риск PHP-only:** запись в существующий inode не атомарна: аварийная partial write и несовместимые с flock внешние писатели остаются возможными; отмечать `MUTATION_OUTCOME_UNCERTAIN` и требовать независимой проверки, а не заявлять невозможную математическую гарантию. `strict` — прежняя экспериментальная явная опция, не обязательный runtime-контракт обычного обновления. Не включать автоматически.

**Исключение из полной обратной совместимости, которое нельзя скрывать:** из-за обязательных CAS-предусловий старые клиенты, отправляющие мутации без `_runtime_preconditions`, получают `CAS_REQUIRED`; это существующее осознанное изменение контракта 1.2.8, а не дефект B3-01/B3-02. Требуется отдельная проверка совместимости установленных клиентов и понятное описание вариантов обновления; нельзя писать, что обновление серверного компонента безусловно сохраняет работу *любого* клиента. Чтение и штатный PHP-хостинг не должны требовать новых установок.

## Что не блокирует Beta, но требует честного сообщения

- Ни проверка TV, ни политика доступа, ни проверка SHA медиа не сериализуют все действия MODX Manager, SFTP и сторонних модулей.
- Media Source с нестандартным драйвером может не поддерживать безопасную автоматическую перезапись.
- Обычный `error.log` — общий журнал MODX: эвристическое маскирование не доказывает удаление всех произвольных секретов. Для секретных инсталляций ограничить доступ к этому инструменту и журналу.
- Миграция ACL-индекса на существующих установках — отдельная административная процедура с резервной копией и явным запуском. Beta не меняет схему БД молча.
- Для protected режима Ed25519/операционный журнал нужна настройка; механизм не становится включённым только от обновления транспортного пакета.

## Контракт релиза

**Остановка до записи:** `CAS_REQUIRED`, `STALE_STATE`, `MANUAL_REVIEW_REQUIRED`; значение `outcome=not_applied` допустимо только до внешнего эффекта.

**Неизвестный исход:** `MUTATION_OUTCOME_UNCERTAIN`; никаких автоматических повторов и компенсирующего отката без независимой проверки. Сообщение пользователю содержит причину и следующий безопасный шаг, но не секреты или сырой код ошибок.

**Версионирование:** в тестовом исходнике транспортные маркеры пока `1.2.7` для воспроизводимости процедуры staging. Beta-сборка создаёт собственные подписи `1.2.8-betaN` на одноразовом runner. Публичный стабильный выпуск и тег требуют отдельного решения.


## Зафиксированное решение Beta 5 (24.11.2026)

PR #186 объединён в тестовую ветку: 7670437e68df1a230ebb8e3af5c4c22b33529c86. CI 4/4, disposable MODX 2/3 12/12, upgrade 2/2 и сборка Beta 4 3/3 завершились успешно. Beta 4 удалена из GitHub Releases по решению владельца. Экспериментальное ослабление CAS из ветки server-only не входит в новый кандидат.

Обязательный CAS сохраняется. Существующие пользователи Node-моста при необходимости обновляют клиент; прямой HTTP не требует установки Node. Штатный portable не требует Python, proc_open или новой настройки хостинга. Экспериментальный strict остаётся добровольным, с явной зависимостью; отдельная ACL-миграция не является автоматической частью установки и может быть необходима для отдельных операций. Ограничения указаны в отдельном документе. Никакой новой архитектуры CAS. Beta 5 — отдельная сборка; публикация только по отдельному разрешению владельца.
