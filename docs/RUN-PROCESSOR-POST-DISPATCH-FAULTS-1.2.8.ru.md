# `run_processor`: ошибки после выполнения стороннего процессора

Дата: 22 ноября 2026. Область: PR #49, тестовая MODX MCP 1.2.8.

Сторонний процессор мог изменить сайт до возврата результата. В коде `RunProcessorTool` вызовы `isError()`, чтение/декодирование ответа и аудит ранее находились за пределами блока подавления исключений выполнения. Если они выбрасывали исключение, наружу мог попасть текст стороннего кода, а ошибка не содержала `MUTATION_OUTCOME_UNCERTAIN`.

Исправление: после запуска процессора весь разбор ответа, очистка секретов и аудит защищены обработчиком неожиданных исключений. Если результат невозможно достоверно подтвердить, возвращается безопасное `MUTATION_OUTCOME_UNCERTAIN` с требованием независимого чтения состояния до повторной команды. Уже классифицированная неопределённая ошибка сохраняет исходное безопасное сообщение.

Тест `_build/test.processor-master-switch.php` искусственно бросает исключение при `isError()` и `getResponse()`, проверяет маскирование секретной строки и требование readback, без реального стороннего процессора. Тесты общего CI и disposable MODX 2/3 подтверждают обратную совместимость, но не доказывают обратимость отправки почты, событий и файловых операций чужих процессоров.
