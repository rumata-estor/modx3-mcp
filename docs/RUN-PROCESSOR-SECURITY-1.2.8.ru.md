# `run_processor`: аудит и усиление в тестовой MODX MCP 1.2.8

Дата: 22 ноября 2026 г. Изменения предназначены только для тестовой ветки 1.2.8 / PR #49.

## Подтверждённые защитные механизмы до этого исправления

- `modxmcp.allow_run_processor` по умолчанию выключен; в защищённом режиме читается из БД, не из кеша MODX.
- Обычный режим требует точный путь из `modxmcp.allowed_processors`; привилегированные пути требуют разрешение через Ed25519 и отдельную политику сайта.
- Произвольные `processors_path` не принимаются, системные процессоры изменения доверенных настроек запрещены, разрешение Ed25519 связано с точным содержимым запроса и одноразовым nonce.
- При исключении или ошибке процессора результат маркируется `MUTATION_OUTCOME_UNCERTAIN`; текст стороннего исключения не возвращается. Ревизия CAS резервируется до запуска.

## Исправления этого аудита

1. В обычном режиме главный переключатель теперь допускает только явные значения `true`, `1`, `'1'`. Строки `'false'`, `'off'`, `'yes'`, другие непустые значения и некорректные числа не включают выполнение через неявное PHP-приведение `(bool)`.
2. `properties` обязан быть массивом параметров (JSON object); указанный `null`, строка, число или boolean отклоняется до запуска. В защищённом режиме проверка выполняется также в `ProcessorAccessPolicy::authorize()` до резервирования nonce. Это исключает молчаливый запуск с пустыми параметрами вместо запрошенных.
3. Универсальная маскировка ответа дополнена ключами секретов в camelCase, snake_case и kebab-case, например `dbPassword`, `smtp_password`, `apiToken`, `clientSecret`, `authorizationHeader`, `access-token`, `password_hash`, `cookie`. Нормальные поля (`id`, `title`, `username`) продолжают возвращаться.

## Проверки и ограничения

Сценарии `_build/test.processor-master-switch.php`, `_build/test.protected-processor-denial.php` и `_build/test.processor-secret-redaction.php` проверяют отказ до `runProcessor`, валидные штатные разрешения и редактирование ответов. Результаты общего CI и disposable MODX 2/3 указываются в PR после выполнения.

Это усиление не доказывает обратимость внешних эффектов стороннего процессора, произвольных плагинов, отправки писем и сторонних сетевых запросов. Внешние эффекты требуют отдельной проверки намерений, readback и восстановления; не выполнять их на production для проверки.
