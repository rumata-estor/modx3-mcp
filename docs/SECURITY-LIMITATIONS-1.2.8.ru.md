# Ограничения безопасности MODX MCP 1.2.8 Beta

> **Мы не гарантируем математическое отсутствие всех конфликтов; мы гарантируем предсказуемое поведение системы и честное сообщение об ограничениях.**

Этот документ фиксирует **принятую границу безопасности** Beta и порядок действий при неоднозначном результате. Он не является сертификатом отсутствия уязвимостей. Не объявляйте отдельные успешные тесты универсальной гарантией безопасности всех дополнений, драйверов или вариантов размещения.

## Область ответственности

MODX MCP предоставляет инструменты чтения и изменения данных через **штатные объекты, процессоры и Media Sources MODX**. При доработке трёх P1 (TV, медиа, политики) мы не вводим собственные SQL-команды записи, новые блокировки таблиц и прямую запись медиафайлов в обход MODX. У системы существуют ранее реализованные механизмы CAS/ревизий и координации; они не должны трактоваться как возможность контролировать все сторонние процессы.

Ни MODX Manager, ни сторонний плагин, ни внешний редактор файлов не обязаны брать блокировку MCP. Между последним чтением и записью остаётся интервал гонки (TOCTOU). **Для Beta это известное, документированное ограничение, а не скрытая гарантия.**

## Три P1: принятый способ снижения риска

| Сценарий | Что проверяет MCP | Что остаётся ограничением |
| --- | --- | --- |
| **Изменение TV ресурса** | Обязательные CAS-предусловия, точные исходные `expected_tvs` и повторное чтение сырого значения штатным API MODX непосредственно перед каждым `setTVValue()`. При несовпадении — `STALE_STATE`. | Внешняя запись после последнего сравнения может победить. Это не глобальная блокировка всех редакторов. |
| **Перезапись медиафайла** | Клиент должен передать `expected_sha256` из полного, сверенного чтения; сервер до записи и непосредственно перед `updateObject()` перечитывает содержимое через `Media Source::getObjectContents()` и сравнивает хеш. Если чтение недоступно или данные изменились — отказ. | Хеш не является атомарным CAS на уровне удалённого хранилища. Нестандартный драйвер может не предоставлять проверяемое содержимое. Успешная проверка не исключает внешней записи сразу после неё. |
| **Изменение/удаление политики доступа и шаблона политики** | Требуется точный полный `read_set` целевой политики из `get_site_state`; для шаблона в хеш включаются доступные через MODX связанные разрешения. Если снимок недоступен либо устарел — отказ. | Другие ACL-сущности и внешние изменения после последнего снимка не становятся атомарно защищёнными этим механизмом. Это не полное решение конкурентного редактирования всех ACL. |

Для медиа хеш возвращается только при полном чтении `modx_read_media_source_file`, если содержимое удалось сверить с родным Media Source. **Не вычисляйте `expected_sha256` самостоятельно по предполагаемому файлу или по частичному ответу.** Отсутствие хеша означает, что автоматическая перезапись в данном сценарии не поддерживается.

Для политики и шаблона используйте серверный `get_site_state` с `read_set` вида `{"role":"target","type":"access_policy","id":123}` или `{"role":"target","type":"access_policy_template","id":123}`, затем передавайте выданный fingerprint вместе с ревизией в `_runtime_preconditions`. Не придумывайте значения fingerprint и не заменяйте их хешами из внешнего клиента. Возможность просмотра объекта через MODX не заменяет требуемого снимка.

## Чтение файлов компонентов и доверенная файловая система

Для `read_component_file` чтение выполняется только через Python 3 на POSIX-хосте с поддержкой `openat`/`O_NOFOLLOW`, с закреплёнными дескрипторами каталогов и ограничением возвращаемых данных до 4 МиБ. Нет повторного открытия файла по имени после `realpath`. Симлинки на пути к запрашиваемому файлу отклоняются (включая симлинки внутри разрешённого дерева). Если Python 3, `proc_open` или необходимые POSIX-функции недоступны, запрос завершится `MANUAL_REVIEW_REQUIRED`, без небезопасного резервного чтения. На хостингах с нестандартными симлинковыми путями необходимо проверить возможность такого чтения **до** обновления.

Это чтение **не записывает файлы**, не требует новых SQL-блокировок и не управляет внешними локальными процессами. Иные операции с Media Source и чтением файлов не получают автоматически той же гарантии. Не объявляйте все файловые маршруты полностью защищёнными от внешнего автора.

## Когда остановиться

- **`CAS_REQUIRED`** — нет обязательного снимка; запись не начинается. Перечитайте состояние и сформируйте новый запрос.
- **`STALE_STATE`** — обнаружено изменение; запись остановлена. Сравните обе версии, согласуйте новый вариант.
- **`MANUAL_REVIEW_REQUIRED`** — невозможно надёжно подтвердить безопасность автоматического изменения; операция останавливается до опасной записи. Проверьте объект в MODX Manager. Не отключайте проверку ради повтора.
- **`MUTATION_OUTCOME_UNCERTAIN`** — возможно, внешний эффект уже начался. **Не повторяйте операцию и не выполняйте компенсирующий откат автоматически.** Сначала установите фактическое состояние отдельным чтением и согласуйте дальнейшие действия.

Коды и машинные поля результата сохраняются для клиентов: `outcome=not_applied` используется, только если отказ произошёл до побочного эффекта; `outcome=unknown` — если результат нельзя подтвердить. Диагностика не должна раскрывать секреты, SQL или содержимое медиа.

## Осознанный компромисс для Beta

Цель — снижать вероятность случайной потери данных, обнаруживать типовые конфликты и **не скрывать остаточный риск**, а не создавать универсальный механизм распределённых транзакций вокруг всей CMS. Для критичных сайтов нужны независимые резервные копии, проверка прав и человеческое согласование опасных изменений.

**Критерий выпуска:** тесты MODX 2/3 и регрессии ошибок должны пройти; риск оставшейся TOCTOU-гонки явно описан. Даже зелёные тесты не превращают best-effort проверку в стопроцентную гарантию.

Документ относится к кандидату **1.2.8 Beta**. Он не утверждает, что эти изменения уже опубликованы в стабильной версии.
