# MODX MCP — қауіпсіздік және сенім моделі

[English](SECURITY.md) · [Русский](SECURITY.ru.md) · [Español](SECURITY.es.md) · [Deutsch](SECURITY.de.md) · [Français](SECURITY.fr.md) · [Українська](SECURITY.uk.md) · [Қазақша](SECURITY.kk.md) · [Nederlands](SECURITY.nl.md) · [Polski](SECURITY.pl.md) · [Орнату](INSTALL.kk.md) · [Мүмкіндіктер](CAPABILITIES.kk.md) · [API](API.kk.md)

Бұл нұсқаулық жария **MODX MCP 1.2.5** нұсқасының сенім шекарасын, қауіпсіздік баптауларын және маңызды шектеулерін сипаттайды. Ол сыртқы агенттерді басқару инфрақұрылымын сипаттамайды.

## Негізгі ереже

**MODX MCP API токенін әкімшілік қолжетімділік дерегі ретінде қарастырыңыз.** Соңғы нүктенің URL мекенжайын немесе құжатталған құрал атауларын білу ғана сұрауға рұқсат бермейді. Алайда жарамды `X-MCP-Token` сайтта ауқымды өзгерістер жасауға мүмкіндік беруі мүмкін.

Сұрауды аутентификациялағаннан кейін сервер MODX **`sudo`** құқықтары бар қызметтік тіркелгіні таңдайды. `modxmcp.service_user_id` белсенді `sudo` тіркелгісін көрсете алады; әдепкі нөл мәнінде бірінші белсенді `sudo` пайдаланушысы таңдалады. Бұл оператордың басқару панеліндегі жеке рұқсаттарына негізделген, әр сыртқы пайдаланушыға бөлек қолданылатын авторизация **емес**.

Токен иесі сниппеттерді, плагиндерді, шаблондарды, ресурстарды, баптауларды және өзге де маңызды мазмұнды өзгерте алады. Орындалатын MODX элементтеріндегі PHP кодын өңдеу веб-қолданба процесінің құқықтарымен еркін PHP кодын орындауға әкелуі мүмкін.

## PHP соңғы нүктесінің қорғаныстары

| Бақылау тетігі | Жұмыс тәртібі және шектеулері |
| --- | --- |
| Токен | `X-MCP-Token` талап етіледі; `modxmcp.api_token` баптауымен салыстырылады. |
| HTTPS | `modxmcp.require_https` әдепкіде қосулы; TLS аяқталатын тораптың конфигурациясын тексеріңіз. |
| IP рұқсат тізімі | `modxmcp.allowed_ips` `REMOTE_ADDR` мәнін нақты IP мекенжайларымен немесе IPv4 CIDR ауқымдарымен салыстырады; бос болса, кез келген қосылушы мекенжайына рұқсат беріледі. |
| Кері прокси | `modxmcp.trust_proxy_https` әдепкіде өшірулі; тек сенімді, дұрыс бапталған кері прокси артында қосыңыз. |
| Негізгі қосқыш | `modxmcp.enabled` өшірулі болса, аутентификацияланған API операцияларын өшіреді. |
| Өлшем шегі | `modxmcp.max_payload_bytes` кіріс JSON деректерінің өлшемін шектейді. |
| Процессорды тікелей шақыру жолы | `modxmcp.allow_run_processor` әдепкіде өшірулі. |
| Мүмкіндік топтары | `modxmcp.disabled_groups` таңдалған құрал топтарын өшіреді. |

**Өшірілген құрал топтары толық авторизация шекарасын құрмайды.** Жүйелік баптауларды жасау/жаңарту/жоюға арналған стандартты құралдар `modxmcp.` префиксінен басталатын кілттерді, соның ішінде басқа баптаулардың атын осы префикске ауыстыру әрекеттерін қабылдамайды. Токенді ауыстыру бөлек артықшылықты әрекет болып қалады. Бұл оқшауланған қауіпсіз орта емес: орындалатын PHP кодын өңдей алатын (немесе арнайы қосылған процессорларды шақыра алатын) аутентификацияланған шақырушы сайт қауіпсіздігіне әлі де әсер ете алады. Әртүрлі операторлар үшін сервер жағында тәуелсіз авторизация тетіктері қажет.

Соңғы нүктеде аутентификацияның дұрыс жұмыс істеуі сұрау жиілігін шектеу кіріктірілген дегенді білдірмейді. Орналастыруыңызға жиілік шектеулері қажет болса, оларды кері прокси немесе веб-сервер деңгейінде енгізіңіз.

## Стандартты Node.js MCP клиенті және тікелей HTTP шақырулары

Жинақтағы Node.js клиентінде кейбір өзгертулерге арналған қосымша қорғаныстар бар: белгілі бір нысандарды өзгерту алдында сақтық көшірме жасау, қауіпті операцияларды орта айнымалылары арқылы әдейі қосу және шақыруларды үйлестіру. **Тікелей `api.php` файлына POST жіберетін арнайы клиенттер осы клиенттік қорғаныстарды орындамайды.**

PHP сервері де кейбір өзгертулер үшін бұғаттау мен алғышарттарды тексеруді, сондай-ақ аудит жазбаларын іске асырады. Бұлар тікелей HTTP қолжетімділігін стандартты MCP клиенті арқылы жұмыс істеуге тең етпейді.

Өз HTTP интеграцияңызды жазсаңыз, сақтық көшірмелерді, авторизацияны, растауларды және қалпына келтіру рәсімдерін өзіңіз іске асырыңыз.

## Ұсынылатын өндірістік конфигурация

1. Жарамды сертификаты бар HTTPS пайдаланыңыз.
2. Токенді қорғалған клиент конфигурациясында немесе құпияларды басқару жүйесінде сақтаңыз. Оны URL мекенжайларына, жария кодқа, скриншоттарға, қолдау өтінімдеріне немесе журналдарға ешқашан қоспаңыз.
3. Мүмкін болса, соңғы нүктеге қолжетімділікті белгілі клиент IP мекенжайларымен немесе қорғалған желімен/проксимен шектеңіз. PHP нақты қай мекенжайды `REMOTE_ADDR` ретінде көретінін тексеріңіз.
4. Арнайы қажеттілік болмаса, `modxmcp.allow_run_processor = 0` күйінде ұстаңыз.
5. Пайдаланылмайтын мүмкіндік топтарын өшіріңіз, бірақ мұның әр пайдаланушыға жеке қолжетімділікті басқару емес екенін ескеріңіз.
6. Өндірістік ортада `modxmcp.debug` өшірулі болсын.
7. MODX сайты мен дерекқорының тәуелсіз, тексерілген сақтық көшірмелерін ұстаңыз.
8. Деректерді жоятын жаппай құралдарда қолжетімді болса `dry_run` пайдаланыңыз; кодқа, рұқсаттарға және баптауларға әсері жоғары өзгерістерді қолмен растаңыз.
9. Токеннің құпиялығы бұзылды деген күдік болса, API токенін ауыстырыңыз; барлық рұқсат етілген клиент конфигурацияларын дереу жаңартыңыз.

## Құрал жауаптарындағы құпиялар мен жеке ақпарат

`modx_list_system_settings` және `modx_get_system_setting` **API токендері мен басқа құпиялар** бар мәндерді қайтара алады. Құпиялылық тәуекелін бағаламай, толық нәтижелерді жария журналдарға, қате есептеріне, аналитика ағындарына немесе сыртқы модельге жібермеңіз.

Оқылған файлдарда, қате журналдарында, пайдаланушы жазбаларында және интернет-дүкен тапсырыстарының деректерінде де жеке немесе құпия ақпарат болуы мүмкін.

## Қорғаныс ауқымы

Құжаттама ЖИ клиентінің сұрауды қате түсінуіне жол бермей қоя алмайды. Ортақ сниппетке, плагинге немесе шаблонға енгізілген бір өзгеріс бірнеше бетке әсер етуі мүмкін. Бірнеше операторға әртүрлі құқық беретін кез келген қолданба бұл құқықтарды тек промпт нұсқауларымен немесе жасырылған құралдар тізімімен емес, өзінің сенімді сервер шекарасының ішінде қамтамасыз етуі керек.

Осалдық тапсаңыз, жұмыс істейтін тіркелгі деректерін немесе клиент деректерін жария GitHub мәселесіне орналастырмаңыз. Ашылып қалған құпияларды кері қайтарып, сүйемелдеушілер мәселені қауіпсіз қайталай алатындай жеткілікті, құпия деректері тазартылған ақпарат беріңіз.

## Ресурс TV мәндерін қатар өзгерту және CAS v2

MODX 2 және MODX 3 үшін жарияланған 1.2.3 тасымалдау пакетінен бастап, `get_site_state` Connector жағындағы TV CAS үшін `precondition_version=2` деп хабарлайды. Қорғалған `modx_update_resource_tvs` сұрауы Runtime басқаратын `_runtime_preconditions` деректерін қамтиды: оқылған сайт ревизиясы, ревизия сәйкестігін қатаң талап ету және дәл өзгертілетін TV атаулары бар `expected_tvs` картасы. Connector бұл шарттарды сайт өзгерістерінің бұғаттауы аясында тексеріп, ескірген мәндерді үнсіз қайта жазудың орнына қабылдамайды.

**Шектеу:** бастапқы MCP схемасы осы ішкі қорғанысты міндеттемейді, сондықтан қорғалмаған тікелей шақыруды қатар жұмыс істейтін агенттерге қатысты қауіпсіз деп көрсетуге **болмайды**. Site Agent пайдаланушылары тексерілген Runtime `modx-tv-change` немесе Executor жолын қолдануы керек. Сәтсіз CAS шақырулары соқыр қайталауды емес, жаңадан оқуды және жаңа жоспарды талап етеді.
