# Безопасность MODX MCP

[English](SECURITY.md) | **Русский** · [Установка](INSTALL.ru.md) · [Возможности](CAPABILITIES.ru.md) · [API](API.ru.md)

Этот документ описывает **реальную модель доверия публичного MODX MCP**, настройки защиты и ограничения. Он относится к интерфейсу версии **1.2.0**, а не к внешним системам управления агентами.

## Главный принцип

**API-токен MODX MCP является административным секретом.** Сама публикация адреса `api.php`, списка команд или их параметров не предоставляет право выполнять запросы. Однако действительный `X-MCP-Token` открывает широкие возможности изменения сайта.

После проверки токена сервер выбирает служебную учётную запись MODX с правами **`sudo`**. Значение `modxmcp.service_user_id` может задавать конкретного действующего `sudo`-пользователя; при нулевом значении выбирается первый активный `sudo`. Это **не** модель отдельного доступа каждого внешнего пользователя с учётом его прав в менеджере.

Обладатель действительного токена может потенциально изменять сниппеты, плагины, шаблоны, ресурсы, настройки и другие критические данные. Изменение PHP-кода сниппетов и плагинов способно привести к исполнению произвольного PHP от имени процесса веб-сервера.

## Защитные механизмы PHP endpoint

| Механизм | Реализация / ограничение |
| --- | --- |
| Токен | Обязательный `X-MCP-Token`; сервер сравнивает его с `modxmcp.api_token`. |
| HTTPS | `modxmcp.require_https` включена по умолчанию; проверьте корректность TLS-терминации. |
| Адреса клиентов | `modxmcp.allowed_ips` позволяет ограничить `REMOTE_ADDR` списком IP или IPv4 CIDR; пустое значение не ограничивает обращения. |
| Доверие прокси | `modxmcp.trust_proxy_https` по умолчанию выключено. Разрешайте его только при контролируемом обратном прокси. |
| Отключение | `modxmcp.enabled` запрещает административные запросы к API при выключенном компоненте. |
| Размер запроса | `modxmcp.max_payload_bytes` ограничивает размер JSON. |
| Выполнение процессоров | `modxmcp.allow_run_processor` выключено по умолчанию. |
| Группы функций | `modxmcp.disabled_groups` может отключать выбранные группы возможностей. |

Не считайте перечень отключённых групп полноценным разграничением прав. Штатные команды создания, обновления и удаления системных настроек запрещают изменения ключей с префиксом `modxmcp.`, включая переименование в этот префикс. Отдельная команда перевыпуска токена остаётся доступной. Это не песочница: авторизованный клиент, способный менять исполняемый PHP-код (или запускать разрешённые процессоры), сохраняет возможность влиять на безопасность сайта. Для пользователей с разными правами нужна отдельная серверная проверка полномочий.

Сама по себе проверка токена не означает наличия встроенного ограничения частоты попыток. При необходимости добавьте ограничения запросов на веб-сервере или обратном прокси.

## Разница между стандартным MCP-клиентом и прямым HTTP API

Штатный Node.js MCP-клиент содержит дополнительные защитные проверки некоторых изменяющих операций: предварительное копирование определённых объектов, ограничения опасных действий через переменные окружения и координацию вызовов. **При обращении напрямую к `api.php` эти проверки клиента не выполняются.**

На стороне PHP существуют отдельные механизмы блокировки для части изменяющих команд, проверки предпосылок и журналирования. Их наличие не делает прямой HTTP-вызов эквивалентным стандартному клиенту по безопасности.

Разрабатывая собственную интеграцию, не рассчитывайте на резервные копии и подтверждения только потому, что действие поддерживается сервером. Обеспечьте их самостоятельно.

## Практические рекомендации

1. Используйте только HTTPS и проверенный сертификат.
2. Храните токен в защищённой конфигурации клиента или менеджере секретов. Не включайте его в URL, Git, скриншоты, сообщения об ошибках и публичные журналы.
3. По возможности ограничьте доступ к `api.php` по IP или на уровне обратного прокси/сети. Проверьте, какое значение `REMOTE_ADDR` реально видит PHP.
4. Оставляйте `modxmcp.allow_run_processor = 0`, если прямой вызов процессоров не требуется.
5. Не включайте ненужные группы возможностей, но не рассматривайте это как полноценную изоляцию прав.
6. Не включайте подробный `modxmcp.debug` на производственном сайте.
7. Применяйте резервное копирование сайта и базы данных независимо от действий клиента; тестируйте восстановление.
8. Для массовых удалений и замен сначала запускайте `dry_run`, если инструмент его поддерживает. Проверка человеком особенно важна для PHP-кода, доступов и настроек.
9. Отзывайте и перевыпускайте токен, если есть подозрение на компрометацию. После ротации обновите все клиентские конфигурации.

## Секреты в ответах API

`modx_list_system_settings` и `modx_get_system_setting` возвращают значения системных настроек, которые **могут содержать токены и другие секреты**. Не передавайте полные ответы таких команд в публичные протоколы, системы аналитики, отчёты или внешние модели без оценки риска.

Аналогичные правила распространяются на содержимое файлов, журналы ошибок, информацию о пользователях и заказах дополнений.

## Какие риски документация не устраняет

Документирование команд не гарантирует защиту от ошибок агента. На рабочем сайте ошибка может затронуть общий шаблон, плагин, сниппет или массовую выборку ресурсов. Права внешних операторов должны проверяться **в доверенном серверном контуре**, а не только инструкциями агенту и не только клиентским списком инструментов.

При обнаружении уязвимости не публикуйте действующие токены и персональные данные в открытых задачах GitHub. Отзовите скомпрометированные секреты и сообщите сопровождающим проекта достаточные технические сведения для воспроизведения без доступа к рабочему сайту.
