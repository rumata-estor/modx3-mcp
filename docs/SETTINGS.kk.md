# MODX MCP жүйелік баптаулары

[English](SETTINGS.md) · [Русский](SETTINGS.ru.md) · [Español](SETTINGS.es.md) · [Deutsch](SETTINGS.de.md) · [Français](SETTINGS.fr.md) · [Українська](SETTINGS.uk.md) · [Қазақша](SETTINGS.kk.md) · [Nederlands](SETTINGS.nl.md) · [Polski](SETTINGS.pl.md) · [Орнату](INSTALL.kk.md) · [Қауіпсіздік](SECURITY.kk.md)

MODX 2.8.x және 3.x жүйелеріндегі **MODX MCP 1.2.5** үшін. Бұл құжат екі тасымалдау пакетінде анықталған **барлық 16 жүйелік баптауды** қамтиды. Әдепкі мәндер `_build/data/transport.settings.php` файлынан алынған; жұмыс тәртібі PHP іске асыруымен салыстырылып тексерілген.

MODX басқару панелінде: **System → System Settings**, `modxmcp` атаулар кеңістігі. **Components → MODX MCP** бөлімі де Audit log, Auto-static, мүмкіндік топтарын өзгертуге және API токенін қауіпсіз көруге/көшіруге мүмкіндік береді. Қалған параметрлерді System Settings бөлімінде өзгертіңіз. Қажет болғанда MODX кэштерін жаңартыңыз және өзгерістерден кейін MCP клиентінің мүмкіндіктерін жаңартыңыз.

**Қауіпсіздік:** токен арқылы рұқсат етілген операциялар MODX **sudo құқықтары бар қызметтік пайдаланушысының** атынан орындалады. Токенді құпия сақтаңыз. Мүмкіндіктерді қосу/өшіру **рұқсат шекарасын құрмайды**.

## Қосылым және сәйкестендіру

| Баптау | Әдепкі мәні | Мәндері және жұмыс тәртібі |
| --- | --- | --- |
| `modxmcp.enabled` | `0` | `0`: API POST әрекеттері қабылданбайды. `1`: API қосулы. HTTPS шарттары орындалса, шектеулі `GET` жұмыс күйі/нұсқа соңғы нүктесі `0` кезінде де жұмыс істейді. Қолжетімділікті бақылау дайын болғаннан кейін ғана қосыңыз. |
| `modxmcp.api_token` | Пакеттегі мәні бос; орнату кезінде **жоқ болса**, кездейсоқ токен жасалады | `X-MCP-Token` тақырыбымен жіберілетін құпия жол. Токен жоқ немесе қате болса, `401` қайтарылады. Қалыпты жаңартулар токенді сақтайды. `settings` рұқсаты бар басқарушылар **Show** / **Copy** пайдалана алады. Токенді ауыстыру қолданыстағы клиент тіркелгі деректерін жарамсыз етеді. |
| `modxmcp.service_user_id` | `0` | `0` ID бойынша бірінші **белсенді sudo MODX пайдаланушысын** таңдайды; оң ID үшін бар әрі белсенді sudo тіркелгісі қажет. Мінез-құлықтың болжамды болуы үшін арнайы қызметтік тіркелгіні таңдаңыз. Бұл сыртқы MCP клиентінің сәйкестігі емес. |

## Желі және қауіпсіздік

| Баптау | Әдепкі мәні | Мәндері және жұмыс тәртібі |
| --- | --- | --- |
| `modxmcp.require_https` | `1` | `0`/`1`. HTTPS талап етеді, соның ішінде `GET` жұмыс күйі жауабы үшін де; әйтпесе `403` қайтарады. Жұмыс істеп тұрған сайттарда `1` күйінде ұстаңыз. |
| `modxmcp.trust_proxy_https` | `0` | `0`/`1`. Қосылса, `X-Forwarded-Proto: https` HTTPS дәлелі ретінде қабылданады. Клиент жіберген тақырыптарды қайта жазатын сенімді кері прокси артында ғана қосыңыз. |
| `modxmcp.allowed_ips` | Бос | Үтірмен бөлінген нақты IP мекенжайлары және **IPv4 CIDR**, мысалы `203.0.113.5,198.51.100.0/24`. Бос мән жарамды токені бар кез келген көзге рұқсат береді. `X-Forwarded-For` **емес**, `REMOTE_ADDR` тексеріледі. Нақты IPv6 сәйкестігі жұмыс істейді; IPv6 CIDR жұмыс істемейді. Қате мәндер `403` қатесіне әкеледі. |
| `modxmcp.disabled_groups` | `versionx,virtualpage,minishop2,migx,access,property_sets,contexts,package_management,namespaces,lexicon` | Үтірмен бөлінген өшірілген топтар: `versionx`, `virtualpage`, `minishop2`, `migx`, `clientconfig`, `access`, `property_sets`, `contexts`, `package_management`, `namespaces`, `lexicon`. Бос мән өзге талаптар бойынша қолдау көрсетілетін барлық топтарды қосады. **Қауіпсіздік рөлдерінің шекарасы емес**; негізгі әрекеттер сайтты әлі де өзгерте алады. |
| `modxmcp.allow_run_processor` | `0` | `0`/`1`. Жалпы `run_processor` операциясына, соның ішінде арнайы MODX процессорларына рұқсат береді. Әкімшілік операциялар ауқымын кеңейтеді: арнайы қажеттілік болмаса, өшірулі ұстаңыз. |
| `modxmcp.allow_root_filesystem_read` | `0` | `0`/`1`. Түбірлік `Filesystem` медиа көзін шолуға және оқуға рұқсат береді. Сервер файлдарының кеңірек ауқымын ашуы мүмкін. Қажет болмаса, өшірулі ұстаңыз. |
| `modxmcp.component_code_roots` | `core/components,assets/components` | Үтірмен бөлінген компонент кодының каталогтары; `base_path` жолына қатысты немесе абсолютті. `{core_path}`, `{assets_path}`, `{base_path}` орынбасарларын қолдайды. **Тек компонент кодын зерттеуді** шектейді, MCP файлдық жүйе әрекеттерінің бәрін емес. Сервердің файлдық жүйе түбіріне дейін кеңейтпеңіз. |

## Шектеулер

| Баптау | Әдепкі мәні | Мәндері және жұмыс тәртібі |
| --- | --- | --- |
| `modxmcp.max_payload_bytes` | `1048576` (1 MiB) | HTTP API POST JSON сұрау денесінің байтпен берілген ең үлкен өлшемі; асып кетсе, `413` қайтарылады. `<=0` мәндері бұл тексеруді алып тастайды. Оң жоғарғы шек сақтаңыз. |
| `modxmcp.max_read_bytes` | `262144` (256 KiB) | Файлдарды оқығанда қайтарылатын бөліктің ең үлкен өлшемі; `<=0` болса, 262144 пайдаланылады. Бұл бүкіл файл өлшемінің шегі **емес**: оқу `offset` және `bytes`/`length` пайдалана алады. |

## Жұмыс тәртібі және диагностика

| Баптау | Әдепкі мәні | Мәндері және жұмыс тәртібі |
| --- | --- | --- |
| `modxmcp.auto_static` | `0` | `0`/`1`. Қосылса, MCP арқылы жасалған/жаңартылған чанктер, сниппеттер, шаблондар және плагиндер `core/elements/` ішіндегі статикалық файлдарға айналады. Тиісті жазу рұқсаттары, сақтық көшірмелер және орналастыру тәртібі қажет. |
| `modxmcp.audit_log` | `1` | `0`/`1`. Қолдау көрсетілетін өзгерту әрекеттерін MODX журналдарына және `core/components/modxmcp/logs/audit.log` файлына жазады. Әр сұраудың толық жазбасы **емес**. Өндірістік ортада қолжетімділік пен өлшем бақылауымен қосулы ұстаңыз. |
| `modxmcp.debug` | `0` | `0`/`1`. Қосылса, HTTP қате жауаптарында ішкі ерекшеліктердің егжей-тегжейі көрінуі мүмкін. Өшірулі болса, шақырушылар жалпы қате мен `error_id` алады. Өндірістік ортада `0` күйінде ұстаңыз. |

## Компонент ядросының жолы

| Баптау | Әдепкі мәні | Мәндері және жұмыс тәртібі |
| --- | --- | --- |
| `modxmcp.core_path` | `{core_path}components/modxmcp/` | Компонент ядросының каталогы (`[[++core_path]]` да қабылданады). HTTP API іске асыруды және нұсқаны жүктеу үшін пайдаланады. Тек тексерілген стандартты емес орнатылымдарда өзгертіңіз; қате мәндер API жұмысын бұзады. |

## Алғашқы қауіпсіз қосылым

1. MODX негізгі нұсқаңызға сәйкес тасымалдау пакетін орнатыңыз. Жаңа орнатылымдар `modxmcp.enabled=0` күйінде басталады; токен автоматты түрде жасалады, ал қолданыстағы токендер қалыпты жаңартуларда сақталады.
2. HTTPS, қажет болса IP шектеулерін, кері прокси баптауларын және `service_user_id` баптаңыз.
3. Басқару панеліндегі **Copy** арқылы API токенін MCP клиентінің құпиялар қоймасына салыңыз. Оны жария етпеңіз.
4. Тек қажетті мүмкіндіктерді қосыңыз. Негізді себеп болмаса, `allow_run_processor` және `allow_root_filesystem_read` өшірулі қалсын.
5. API-ді қосып, **аутентификацияланған, тек оқуға арналған әрекетті** тексеріңіз. `GET` нұсқа/жұмыс күйі жауабы клиент токенінің жарамды екенін **дәлелдемейді**.
