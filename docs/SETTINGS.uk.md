# Системні налаштування MODX MCP

[English](SETTINGS.md) · [Русский](SETTINGS.ru.md) · [Español](SETTINGS.es.md) · [Deutsch](SETTINGS.de.md) · [Français](SETTINGS.fr.md) · [Українська](SETTINGS.uk.md) · [Қазақша](SETTINGS.kk.md) · [Nederlands](SETTINGS.nl.md) · [Polski](SETTINGS.pl.md) · [Встановлення](INSTALL.uk.md) · [Безпека](SECURITY.uk.md)

Для **MODX MCP 1.2.4** на MODX 2.8.x і 3.x. Цей документ охоплює всі **16 системних налаштувань**, визначених обома транспортними пакетами. Значення за замовчуванням узято з `_build/data/transport.settings.php`; поведінку звірено з реалізацією PHP.

У менеджері MODX: **Система → Системні налаштування**, простір імен `modxmcp`. **Компоненти → MODX MCP** також дає змогу змінювати Audit log, Auto-static, групи можливостей і безпечно переглядати/копіювати токен API. Інші параметри змінюйте в системних налаштуваннях. За потреби оновлюйте кеші MODX, а після змін оновлюйте можливості MCP-клієнта.

**Безпека:** операції, авторизовані токеном, виконуються від імені **службового користувача MODX із правами sudo**. Зберігайте токен у таємниці. Перемикачі можливостей **не встановлюють межі дозволів**.

## Підключення та ідентичність

| Налаштування | За замовчуванням | Значення та поведінка |
| --- | --- | --- |
| `modxmcp.enabled` | `0` | `0`: дії API через POST відхиляються. `1`: API увімкнено. Обмежена кінцева точка `GET` для перевірки працездатності/версії працює і за `0`, якщо виконано умови HTTPS. Увімкніть лише після підготовки засобів контролю доступу. |
| `modxmcp.api_token` | Порожнє значення в пакеті; випадковий токен створюється під час установлення, **якщо відсутній** | Секретний рядок, що передається в заголовку `X-MCP-Token`. Відсутні/неправильні токени спричиняють `401`. Звичайні оновлення зберігають токен. Користувачі менеджера з дозволом `settings` можуть скористатися **Показати** / **Копіювати**. Ротація токена робить недійсними наявні облікові дані клієнтів. |
| `modxmcp.service_user_id` | `0` | `0` вибирає першого за ID **активного користувача MODX із правами sudo**; додатний ID вимагає наявного активного облікового запису sudo. Для передбачуваної поведінки виберіть окремий службовий обліковий запис. Це не ідентичність зовнішнього MCP-клієнта. |

## Мережа та безпека

| Налаштування | За замовчуванням | Значення та поведінка |
| --- | --- | --- |
| `modxmcp.require_https` | `1` | `0`/`1`. Вимагає HTTPS, зокрема для відповіді `GET` про працездатність, інакше повертає `403`. На розгорнутих сайтах залишайте `1`. |
| `modxmcp.trust_proxy_https` | `0` | `0`/`1`. Якщо увімкнено, `X-Forwarded-Proto: https` приймається як підтвердження HTTPS. Вмикайте лише за довіреного зворотного проксі, який перезаписує заголовки, надані клієнтом. |
| `modxmcp.allowed_ips` | Порожньо | Точні IP-адреси та **IPv4 CIDR**, розділені комами, наприклад `203.0.113.5,198.51.100.0/24`. Порожнє значення дозволяє будь-яке джерело з дійсним токеном. Перевіряє `REMOTE_ADDR`, **а не** `X-Forwarded-For`. Точне зіставлення IPv6 працює; IPv6 CIDR — ні. Неправильні значення спричиняють `403`. |
| `modxmcp.disabled_groups` | `versionx,virtualpage,minishop2,migx,access,property_sets,contexts,package_management,namespaces,lexicon` | Вимкнені групи, розділені комами: `versionx`, `virtualpage`, `minishop2`, `migx`, `clientconfig`, `access`, `property_sets`, `contexts`, `package_management`, `namespaces`, `lexicon`. Порожнє значення вмикає всі групи, які підтримуються за інших умов. **Не є межею рольового контролю доступу**; базові дії все одно можуть змінювати сайт. |
| `modxmcp.allow_run_processor` | `0` | `0`/`1`. Дозволяє загальну операцію `run_processor`, включно з користувацькими процесорами MODX. Розширює коло адміністративних операцій: залишайте вимкненим, якщо немає конкретної потреби. |
| `modxmcp.allow_root_filesystem_read` | `0` | `0`/`1`. Дозволяє перегляд і читання кореневого медіаджерела `Filesystem`. Може відкрити доступ до ширшого набору файлів сервера. Залишайте вимкненим, якщо немає потреби. |
| `modxmcp.component_code_roots` | `core/components,assets/components` | Каталоги вихідного коду компонентів, розділені комами, відносні до `base_path` або абсолютні. Підтримує плейсхолдери `{core_path}`, `{assets_path}`, `{base_path}`. Обмежує **лише дослідження коду компонентів**, а не всі дії MCP із файловою системою. Не розширюйте доступ до кореня файлової системи сервера. |

## Обмеження

| Налаштування | За замовчуванням | Значення та поведінка |
| --- | --- | --- |
| `modxmcp.max_payload_bytes` | `1048576` (1 MiB) | Максимальний розмір тіла JSON-запиту POST до HTTP API в байтах; перевищення спричиняє `413`. Значення `<=0` прибирають цю перевірку. Зберігайте додатну верхню межу. |
| `modxmcp.max_read_bytes` | `262144` (256 KiB) | Максимальний розмір фрагмента, що повертається під час читання файлів; за `<=0` використовується 262144. Це **не** обмеження повного розміру файлу: читання може використовувати `offset` і `bytes`/`length`. |

## Поведінка та діагностика

| Налаштування | За замовчуванням | Значення та поведінка |
| --- | --- | --- |
| `modxmcp.auto_static` | `0` | `0`/`1`. Якщо увімкнено, створені/оновлені через MCP чанки, сніпети, шаблони та плагіни стають статичними файлами в `core/elements/`. Потребує належних прав запису, резервного копіювання та практик розгортання. |
| `modxmcp.audit_log` | `1` | `0`/`1`. Записує підтримувані дії зміни до журналів MODX і `core/components/modxmcp/logs/audit.log`. Це **не** вичерпний запис кожного запиту. У production залишайте увімкненим, контролюючи доступ і розмір. |
| `modxmcp.debug` | `0` | `0`/`1`. Якщо увімкнено, у відповідях HTTP із помилками можуть з’являтися подробиці внутрішніх винятків. Якщо вимкнено, викликачі отримують загальну помилку та `error_id`. У production залишайте `0`. |

## Шлях до ядра компонента

| Налаштування | За замовчуванням | Значення та поведінка |
| --- | --- | --- |
| `modxmcp.core_path` | `{core_path}components/modxmcp/` | Каталог ядра компонента (також приймає `[[++core_path]]`). Використовується HTTP API для завантаження реалізації та версії. Змінюйте лише для перевірених нестандартних інсталяцій; неправильні значення порушують роботу API. |

## Безпечне перше підключення

1. Установіть транспортний пакет, що відповідає вашій основній версії MODX. Нові інсталяції починають із `modxmcp.enabled=0`; токен генерується автоматично, а наявні токени зберігаються під час звичайних оновлень.
2. Налаштуйте HTTPS, за потреби обмеження IP-адрес, параметри зворотного проксі та `service_user_id`.
3. Скористайтеся **Копіювати** на панелі менеджера, щоб помістити токен API до сховища секретів вашого MCP-клієнта. Не розголошуйте його.
4. Увімкніть лише потрібні можливості. Залишайте `allow_run_processor` і `allow_root_filesystem_read` вимкненими без обґрунтованої потреби.
5. Увімкніть API та перевірте **автентифіковану дію лише на читання**. Відповідь `GET` із версією/станом працездатності **не** доводить, що токен клієнта дійсний.
