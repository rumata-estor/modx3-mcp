# Обратная связь по MODX MCP: живой проект (22.11.2026)

**Статус:** весь предоставленный отчёт зарегистрирован к проверке; принятие в реестр не равнозначно готовому исправлению или обещанию релиза. Автор проверял **MODX MCP 1.2.3**, **MODX 3.2.4**, **PHP 8.4**, pdoTools/Fenom, MIGX, ClientConfig, Collections, Gallery3x; 70 страниц и ~110 TV. Наблюдения нужно повторить на тестовой версии 1.2.8. Ничего не делать на production.

## P0 — корректность и безопасность
- **R01** `run_processor` сообщает HTTP 500 после успешного процессора: проверить array/string `getResponse()` и все аналогичные места в PackageSupport/Install/ProcessorSupport. Ответ должен достоверно отражать исходную операцию; не допускать слепых повторов записи.
- **R02** HTTP API молча принимает неизвестные корневые поля (например, `params` вместо `data`): строгая проверка до исполнения, с обратной совместимостью документированных полей.
- **R03** `update_element` для ресурсов сбрасывает несвязанные поля (в частности `richtext`): реальный тест частичного обновления и сохранности остальных полей, MODX 2/3.
- **R04** `create_media_folder` игнорирует `path`: явная валидация `parent/name/path`, никакого создания в неожиданном каталоге.
- **R05** `update_resource_tvs` не принимает массив multi-value TV: проектировать сериализацию `||` без порчи других TV и без обхода raw TV CAS.
- **R06** `get_resource_tvs` отдаёт обработанное значение вместо сырого: предоставить явно `raw` и `rendered` (или документированный режим) с тестами `@INHERIT` и listbox-multiple.
- **R07** Секреты и ошибочные ответы процессоров: защита от утечек и неопределённых результатов, не ослабляя отдельную Ed25519-авторизацию.

## P1 — полнота функциональности
- **R08** ClientConfig: корректная инвалидация собственного кеша после create/update/delete; не полагаться на общий refresh без теста.
- **R09** ClientConfig: пустая строка description не должна превращаться в `0`.
- **R10** Сторонние процессоры ClientConfig: только безопасно зарегистрированный namespace/точные пути, без произвольного `processors_path`.
- **R11** Safety: определить источник сообщений о safe workflow, дать вызывающему агенту диагностику отказа и реальную альтернативу, не раскрывая секретов и не снимая ограничения.
- **R12** Схемы TV: `description`, `rank`, `elements` и нужные параметры с валидацией/тестами на MODX 2/3.
- **R13** Property sets: явная проверка структуры свойств вместо молчаливого повреждения.
- **R14** При создании ресурса учитывать `richtext_default` штатным способом без неожиданного отключения редактора.
- **R15** `auto_static`: явный контролируемый параметр `static:false`; не менять конфигурацию по умолчанию без проверки.
- **R16** При переименовании статических файлов: детектировать сироты; удаление только явно и безопасно.
- **R17** Диагностика запрета `.tpl` — указывать настройку `upload_files`.

## P2 — отдельные защищённые функции
- **R18** `check_template`/Fenom dry-run без изменения production и без выполнения опасных PHP-побочных эффектов.
- **R19** Резервная версия/атомарное сохранение файла; `revert_media_file` с CAS, без автоматического отката по случайному HTTP 500.
- **R20** `$_FILES`/Gallery3x через отдельный разрешённый API с ограничениями размера/типа/пути.
- **R21** Клиентский rate limiting и backoff для чтений; повтор записи только при доказанной идемпотентности и учёте результата предыдущей операции.
- **R22** Неизвестные параметры процессоров: валидация там, где известна схема; предупреждения без ложной уверенности в полноте схемы.

## Ход реализации / Implementation status (22.11.2026)
- **R01** — исправлена обработка JSON/массивов (`4593411`), CI MODX 2/3 прошёл.
- **R02** — неизвестные корневые параметры HTTP отклоняются до записи (`fc7f751`), интеграционный CI прошёл.
- **R04** — неподдерживаемый `path` в create_media_folder теперь вызывает явный отказ, без создания в корне (`bbd78cc`), CI прошёл.
- **R03** — сохранение `richtext`, `searchable`, `cacheable` при content-only update (`10c05bd`), 12 конфигураций успешно.
- **R05** — массивы только для listbox-multiple TV, `||` + raw CAS, тест реального TV (`773f569`), 12 конфигураций успешно.
- **R08** — подтверждена причина расхождения с ручным «Сохранить» в ClientConfig: стабильная 1.2.7 использует общий `$cacheManager->refresh()`, тогда как ClientConfig::getSettings кэширует значения в `system_settings/clientconfig`; штатный Manager удаляет именно этот ключ. В тестовой 1.2.8 адресная инвалидация и событие `ClientConfig_ConfigChange` добавлены в `a3893a2`. Отдельный unit-тест проверяет устаревшее значение до очистки и актуальное после повторного чтения, а также приоритет `context_aware`: глобальный `value` не заменяет `context_values.web`. **Реальный установленный ClientConfig 2.5.0 ещё не испытан**, поэтому эксплуатационное закрытие R08 остаётся условным.
- **R23** — экспериментальный MODX 3.2.4 / PHP 8.4 интеграционный прогон прошёл. Требуется проверка сторонних дополнений.
- **Остальные задачи открыты.** Никакие результаты не доказывают безопасность операций, не покрытых соответствующими сценариями.
